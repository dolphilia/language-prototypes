## 書き方

- 内容がわかる英小文字とハイフンのファイル名を付け、Markdownで記録します。
- 調査日を明記し、更新したときは更新日も記録します。
- 調査で確認した事実と、そこからの考察・仮説・設計案を区別します。
- 技術的な説明には、公式ドキュメント、原論文、開発者の説明などの一次資料を添えます。
- 利点に加え、適用範囲、代償、未解決の点も残します。
- 提案・実験・研究段階の内容を、安定した実装の機能と区別します。
- 新しいメモを追加したら、この一覧からたどれるようにします。
