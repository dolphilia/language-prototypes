## 1. 後続段階の進め方

M1の契約・部品・判定方法を再利用する。E3を領域の論理であるE3aと、機械語の呼び出し元まで接続するE3bに分け、E5をその間に置く。E4はM1の後で着手できる。E6とE7は、対象の命令・契約が固定された時点で着手できる。

各段階で、独立した仕様、必要な定理、実物、正例と誤実装、前提の記録、測定・報告をそろえる。M1の2関数の契約・容量条件は維持し、呼び出し元や新しい関数の資源条件は別に定める。

## 2. E3a — 所有領域から入口条件を導く

### 2.1 最小の領域モデル

HOL内に、領域の所有、部分領域への分割、読み取り借用、排他的な書き込み借用、借用の終了、権限の失効を表す小さな論理を作る。実装は埋め込みの構造と証明補助に限定し、新しい構文のパーサーや一般の借用検査器を作らない。

領域の記録には、開始アドレス、容量、所有の識別、寿命、読書き権限を持たせる。ただし、これらを構造体のフィールドへ書くだけで権限が生まれる設計にはしない。生成・分割・借用の各操作は、必要な前提から定理として導出する。

最初の根は、**呼び出し中有効な通常RAMの所有領域`Owned(arena,L)`が与えられる**という外部契約とする。非NULL、非折り返し、排他的な更新、コードとの非重複を含む。実際のマッピング・アロケータ・OSによる有効性の維持は、この段階で証明したと扱わない。

### 2.2 検査を含む呼び出し元の仕様

一つの領域を位置`split`で分け、先頭の`n`バイトを後ろの部分領域の先頭へコピーする。予定する実験用APIは次とする。

```c
/* 0: コピー成功、1: splitまたは長さが不正。所有領域の有効性は事前条件。 */
int vp2_copy_split(void *arena, size_t L, size_t split, size_t n);
```

まず`0 < split < L`、`n <= split`、`n <= L-split`を検査する。不正な場合はコピーを呼ばず、`arena`内のデータを変更せずに1を返す。`L-split`や部分領域のアドレスを作る前に、必要な範囲条件を確かめる。

成功時は、`src=arena`と`dst=arena+split`について、境界・非重複・非折り返し・権限・寿命を導き、コピーの入口条件へ接続する。単に同じ`n`の条件を呼び出し元の事前条件へ追加して、検査を省略しない。

E3aでは、コピーを既存の契約を持つ抽象的な操作として接続し、成功時の内容・保存状態・借用の返却と、失敗時の領域内の変更なしを証明する。実際の`BL`とバイナリへの対応はE5・E3bで完成させる。

**拒否する例:** 同じ部分領域への重複した排他的借用、容量を越える分割、借用中の失効、失効後の再利用、範囲検査の省略や減算の順序の破壊。寿命違反の論理例を、実機へ不正なポインタを渡す試験としては実行しない。

**通過条件:** 正常な呼び出しの入口条件が領域と検査から導かれ、不正な権限操作を構成できない。外部の所有領域の根と、高水準の権限から平坦な機械メモリへの対応の前提が報告に残る。

Rustのバイトスライスを受けるラッパーは任意の比較用とし、導入する場合も初期化済み`u8`に限定する。実機の試験だけでRustの意味・ポインタの由来・FFI全体の形式検証を達成したとはしない。Rustの処理系全体の検証はM2の必須範囲に含めない。

## 3. E4 — バイト単位の`memmove`

### 3.1 独立した公開契約

```c
void *vp2_memmove(void *dst, const void *src, size_t n);
```

非重複だけを前提から外し、通常RAM、有効性と寿命、非NULL、非折り返し、排他的な更新、出力とコードの非重複は維持する。同一アドレスも扱う。事前条件を満たす任意の`size_t`が対象であり、ゼロ長でデータアクセスなし、戻り値は元の`dst`とする。

事後条件は、出力が**開始時の入力**の`n`バイトと等しいこと、出力と許した一時状態以外を保存することとする。重複時に入力領域全体の不変を要求しない。

### 3.2 実装・証明

最初はバイト単位の前向き・後ろ向きのループに限定する。アドレスの順序で安全な方向を選び、必要なら同一アドレスをそのまま返す。後ろ向きでは、残りの添字を減らしてからアドレスを作るなど、一つ先のアドレスの折り返しへ依存しない方法を使う。

前向きではこれから読む入力の末尾側、後ろ向きでは先頭側が開始時の値を維持することを不変条件にする。読み書きが重なる場合にも、フレーム・アクセス列・有限実行・復帰先・ABIを証明する。

機械語のアドレス比較に対する定理とする。C等へ実装を移す場合に、無関係なポインタの順序を同じように使えるとは仮定しない。

**試験:** 長さ0・1とM1の境界長、ずれ0・±1・±`(n-1)`・±`n`・±`(n+1)`、隣接、両方向、整列のずれ、配置可能なガードページ、番兵、戻り値・ABIを調べる。Cの参照結果は開始時の入力の退避から作り、libcの`memmove`とも比較する。

**破壊例:** 常に前向き、常に後ろ向き、方向の逆転、最初／最後のバイトの欠落、ゼロ長での減算、過剰な読み書き。契約を満たす初期状態からの反例を用意する。

**通過条件:** 非重複を要求しない独立した仕様の全定理と実物の照合が通り、試験・評価がある。カーネルは葉関数、スタック・ヒープ使用ゼロ、証明用の実行費用ゼロ、本体256バイト以下とする。この256バイトはM1の選択した2関数の合計とは別の条件であり、配布する関数全体の合計も報告する。

## 4. E5 — 一つの直接呼び出しとリンク後の証明

### 4.1 対象を限定する

最初は、同じ実行ファイルへ静的に組み込むコピーへの直接呼び出し一つとする。小さな呼び出し用の試験関数で先に接続を通し、その方法をE3bへ適用する。ネストした複数の補助関数や動的解決は扱わない。

対象はAArch64の直接`BL`と、そのために必要なMach-Oの分岐再配置一種類に限定する。具体的な種別・加算値・シンボル参照を小さなオブジェクトで確定する。必要な形式を確認できなければ、未対応のまま受理せず段階未達とする。

呼び出し元だけに、16バイトのスタック枠で復帰先等を保存する構成を採用する。呼び出し先のM1カーネルはスタックを使わない。親の前提には、スタックの整列、有効な16バイト、アドレスの非折り返し、データ領域・コードとの非重複を加え、SPと保存レジスタの復元を証明する。

### 4.2 最初は、リンク後の命令列を証明へ取り込む

1. 再配置前のオブジェクトを調べ、許可した再配置・呼び出し先以外がないことを確認する。
2. 実行ファイルへリンクし、呼び出し元と呼び出し先のバイト列、位置、実際の分岐先を抽出する。
3. リンク後の呼び出し元をHOLへ取り込み、呼び出し先のコードと定理に接続する。
4. 復帰先の保存、引数の受け渡し、フレーム、イベント、スタック量、有限の復帰を証明する。
5. 同じ成果物をCから実行し、結果・ABI・スタックの番兵等を確認する。

ASLRを考慮し、呼び出し元と呼び出し先の相対位置を保つ共通のロード位置を量化する。Mach-Oの望ましい配置先アドレス一つで証明しただけで、実行時の全配置へ対応したとはしない。コードのロードとOSローダーの対応は、残る外部契約として示す。

汎用の「検証済みリンカ」は作らない。最初の達成範囲は、限定したリンク結果の命令列と分岐先の検証である。再配置規則そのものの一般定理は、結果を踏まえた次の拡張とする。

### 4.3 試験と通過条件

リンク順序やパディングを変えた少なくとも2通りの配置で、実物と定理の対応を確認する。各配置の証明・抽出・入力ハッシュを別に記録する。

再配置先の改変、同名の別実装、分岐範囲外、スタブや動的解決の混入、戻り先の破壊、スタックや保存レジスタの不一致を拒否する。シンボル名が一致するだけで接続を受理しない。

**通過条件:** リンク後の呼び出し元と実際の呼び出し先の契約が接続し、2配置の正例・誤実装・実機試験がそろう。16バイトのスタック枠の外側を変更せず、関数復帰時にSPを復元する。抽出器・リンカ・ローダーのうち証明していない部分を記録する。

## 5. E3b — 検査付きの呼び出し元を実物へ接続する

E3aの`vp2_copy_split`を、E5の直接呼び出しの構成で機械語にする。条件を検査する分岐とアドレス計算は呼び出し元の命令について証明し、コピー本体はM1の定理を再利用する。

**必要な結果:** 成功時の内容と保存状態、失敗時の`arena`内の変更なし、入口条件の導出、全経路の終了・復帰、スタックとABI、途中のアクセス。ABIの保存に使うスタック領域の書き換えは、利用者のデータ領域と別のフレームとして明示する。E3aの権限の操作と、生成したコードの実行の対応も示す。

実機では有効な所有領域を用意し、長さと分割位置の正常値、ゼロ長、不正値、最大値付近を試す。最大値の不正な`n`を受け取っても、範囲外コピーへ進まないことを検査する。OSから実際に確保できない巨大な有効領域は、モデル上の証明で扱う。

長さ検査を削る、減算を先にする、二つの領域を重複させる、借用を失効させる等の例を拒否する。ライブラリ本体、ラッパー、長さ検査、関数呼び出しの速度と容量を分けて測る。

**M2の通過条件:** E3a・E3b・E4・E5の必要な定理と実物がそろい、入口条件をどこで導いたかを追跡できる。根となる所有領域とスタックの有効性・OSの維持は前提として残し、「アロケータから呼び出し元まで無条件に安全」とは報告しない。

## 6. E6a — 使用命令のモデル差分検査

### 6.1 最初の互換性確認

候補はSailのArmモデル等の独立した実行バックエンドとする。既存のHOLモデルの関数を再利用して別の表面構文にしただけのものを、独立したモデルと数えない。

まずRETとロード／ストア一組で、対象Arm版、命令形式、初期状態、実行方法、比較できる出力、ライセンス、導入・実行費用を確認する。採用するバックエンドとコミットを固定する。M1で使う命令が扱えない場合は、別の対応バックエンドを調べ、未対応の命令を検査済みの件数に含めない。

### 6.2 比較する範囲

対象はM1の生成したコードで実際に使う命令形式の一覧から決める。バイトと64ビットのロード／ストア、必要なアドレス指定、加減算、比較、ビット演算、条件分岐、復帰を含む。E5の命令を追加する場合は、対象拡張として別に記録する。

各形式について少なくとも32の境界事例と256の固定シードの事例を作り、HOLと独立バックエンドの結果を比較する。同じ事例のうち安全に実行できるものを、静的に構築した実機用の短い命令片でも確認する。任意のアドレスや分岐先を、そのまま実機へ渡さない。

比較対象は、定義された結果のレジスタ、フラグ、指定メモリ、到達した分岐先とする。32ビット書き込みの上位ビット、整列、符号と桁上がり、境界のアドレス計算を重点に置く。非決定的な結果や前提の違う事例を、不一致や一致へ雑に集計しない。

アクセスイベントは、モデル間で対応が定義できる場合に比較する。実機でモデルの全イベント列を直接観測できるとは仮定せず、キャッシュ・投機・電力の検査とも区別する。

**通過条件:** 対象の全命令形式の対応表と再実行可能な事例、比較結果、不一致の切り分けがある。未解決の不一致があれば、影響する命令を含む保証の拡張を停止する。一致した有限の事例から、ISAモデルと全CPUの同値を主張しない。

## 7. E6b — 独立した証明検査の実現性調査

この段階の必須成果物は**調査と再検査の最小実験の記録**であり、独自カーネルや完全な証明輸送機構の新造ではない。

既存の健全性文書が挙げる手法などから、既存の証明出力・再検査の経路を調べる。候補を二つまで比較し、一つを最小実験へ進める。対象はRETのコードに対する小さな正しさの定理とする。

定義、型、公理、推論の出力方法を調べ、別のカーネルで同じ命題を確認できるか試す。定理の文をコピーしたり、その文を公理として読み込んだりする方法は成功としない。正常な証明と、結論や推論を壊した入力の両方を試す。

| 調査結果 | 完了記録に必要なもの |
| --- | --- |
| 再検査成功 | 対象命題・コード・全依存の定義と公理、検査器の版、出力・変換方法、正例と改変拒否、再実行手順 |
| 未対応・再検査未達 | 実際に試した経路と版、入力、診断、足りない定義・推論・形式、実現に必要な追加作業 |

調査だけ完了した場合は「E6b調査完了・独立再検査機能は未達」と表示する。実験を行わず、単に難しいと記述した報告では完了にしない。前提が明らかに非互換で実行に進めない場合も、形式・ツールの一次資料と最小の再現可能な非互換事例を残す。

成功した場合も、共有する仕様、モデル、変換処理、実行環境への信頼を記録する。HOLの閉じた命題を別のカーネルでも確認できたことと、実機・仕様の正しさが新たに証明されたことは区別する。

## 8. E7a — ステップ数とアクセス量の定理

まず既存版の基本ループに対して、コピー`5n+3`、埋め込み`4n+3`という候補を確認し、ステップ数付きの関係で証明する。既存の長さ8専用版の経路別の式も対象とする。これらの式は採用したメモでの数え上げであり、実装開始時点で証明済みとは扱わない。

次に、M1の新しいコードを固定し、`q=n DIV 8`、`r=n MOD 8`と整列経路から、その実際の制御命令を含む式を導く。参考にする基盤は、使用中のs2n-bignumの`common/relational_n.ml`である。

コピーの読み取り・書き込みの合計バイト数、埋め込みの読み取り0と書き込み量、経路別のスタック量も定理または検査可能な導出として記録する。イベントの逆順の蓄積と、回数・幅の数え方を統一する。

**通過条件:** 任意の有効な長さについて、実際のコードに対応した式を機械検査できる。命令を追加・削除した反例では、古い式を受理しない。機能の証明だけから資源の式を自動的に得たことにはしない。

これはモデル上の命令ステップ数・データアクセス量の保証である。CPUのパイプライン、キャッシュ、OS、ページフォルト等を含む秒数の上限の証明は本計画へ含めない。

## 9. E7b — 有限の候補探索と、候補固定後の測定

### 9.1 探索範囲

最初はM1のコピーだけを対象にし、ワード反復の展開数1・2と、許可した一時レジスタの割り当て等から、4〜8候補の固定した集合を作る。使用命令・制御構造・レジスタは検査済みの範囲へ限定する。候補集合と予算は測定前に記録し、自動的に探索範囲を拡大しない。

少なくとも、元の候補、意味を保つ新しい候補一つ、不正な候補一つを含める。元の候補だけが通ることで、新しいコードを検査できたと報告しない。

### 9.2 受理と選択

候補生成器は正しさの根拠にしない。各候補のコード定義と期待する契約を独立に照合し、機能・終了・保存・アクセスと資源の必要条件を確認する。`unknown`と反例を区別し、必要な契約を証明できない候補を配布用に選ばない。

証明された候補だけを探索用の性能比較へ進める。候補を選んだらソース・命令列・証明対象を固定し、新しいプロセスで全検査と独立した確認用の測定を行う。探索時と確認時の入力・順序・測定値を別に保存する。

### 9.3 測定と判定

M1の方法を基本に、短い呼び出しと大きな作業領域を分ける。作業領域を大きくする場合は、機器の情報と利用可能なメモリを確認し、上限を先に決める。キャッシュを追い出す近似操作は、方法と限界を記録する。

遅延、転送量、本体と配置の容量、探索時間、証明時間を別々に比較する。最初の選択規則は、M1の容量資源条件を満たすものについて、整列済み64・256・4096バイトの「候補の中央値÷基本版の中央値」の単純平均をスコアとする。探索用の最小スコアから5%以内の候補では本体が小さいものを選び、同じ大きさならスコアの小さいものを選ぶ。短い長さと未整列の退行も別に表示する。

この規則は探索用の選択であり、測定誤差や他の用途での最適性の保証ではない。選択後の確認用測定で改善が再現しない場合は、そのまま未達／不明と記録する。確認用の結果を見て別候補へ選び直し、同じ結果を独立した確認と呼ぶことはしない。

各確認用ケースは少なくとも7回測り、E0の根拠の種類と、M1の速度判定を維持する。多数の候補の最小測定値を、一般的な最速性や統計的な保証として扱わない。

**通過条件:** 少なくとも一つの新しい正しい候補を証明し、不正な候補を拒否できる。選択された候補と元の候補の比較、未解決の候補、独立した再測定、生データ、探索費用、残る前提の報告がそろう。高速化そのものは支持／未達／不明を別に記す。

| M2 | E3aの領域と条件導出、E4の重複コピー、E5の限定したリンク後の証明、E3bの実行可能な呼び出し元、全ての試験と資源・性能の報告 |
| M3 | E6aの対象全形式の差分検査と不一致の解決、E6bの実現性調査の根拠、E7aの資源の定理、E7bの新候補の検査と選択後の再測定 |

`verify-m2`・`verify-m3`と対応する測定入口を用意し、全体では`verify-all`を実行する。E6bの調査結果が未達の場合は、その事実を最終監査の独立した欄へ残す。必須の実装や定理に未解決が残る場合は、その単位を完了にしない。

最終報告では、論理上の前提の導出、アルゴリズムによる前提の除去、実物との対応の検査、有限の試験、外部への信頼を分ける。結果としてどの負担が軽くなり、どの作業・仮定が増えたかを、元のE0〜E7へ対応づけて記録する。
