# M1 — 根拠の分類、証明の合成、任意長コピー

[全体計画](README.md) · [後続段階](later-stages.md) · [発展方向のE0〜E2](../../notes/verified-libc-next-experiments.md)

状態: **M1完了**。[完了監査](../../../prototypes/verified-libc-evolution/reports/m1/audit.md)でB0・E0・E1・E2の通過条件を照合した。79定理、実機1,109,765件、固定長192例、破壊6例、105ケース各7回の測定、3回の証明・修正費用を保存した。M2・M3を含む[全体の監査](../../../prototypes/verified-libc-evolution/reports/audit.md)も完了した。

## 1. この実装単位で作るもの

1. 証明済み・反例あり・未解決と、基盤異常を区別する検査と報告。
2. コード、契約、導出した定理を結びつける最小のブロック表現と合成処理。
3. Copy8の合成による16・32バイトの試験用処理。
4. 任意長の8バイトループとバイトの端数処理による`memcpy`の新しい版。
5. 直接記述と合成の比較、実物の照合、境界・ABI・破壊試験、性能・容量・証明修正費用の評価。

公開する操作はコピーと埋め込みの2種類のままとする。Copy16・Copy32は合成を確かめる試験用の部品であり、libc関数を大量に増やす入口にはしない。`memset`の高速化、SIMD、未整列のワードアクセス、関数間呼び出しはここへ追加しない。

## 2. B0 — 既存版の再現と、比較条件の固定

発展版を作る前に、既存版のソースと契約を保存済みの記録と照合し、`make verify`を再実行する。機器、OS、Clang、SDK、OCaml、依存コミット、パッケージ、実行形式を記録する。別環境でオブジェクト全体や署名のハッシュまで過去と一致するとは仮定せず、関数本体の対応と現在の検査結果を確かめる。

発展版には独立した`build/`と報告を用意する。既存の証明を取り込む場合は、既存版のルートと発展版のルートを区別し、HOL定数・Cシンボル・結果ファイルの名前が衝突しないようにする。

**成果物:** `reports/baseline.json`、再検査ログ、使用する契約の一覧、測定と修正費用の方法。

**通過条件:** 既存版が再検査でき、比較に使う入力・版・機器を特定できる。ここが通らない場合は、新しい関数の証明へ進まず、導入や版の不一致を切り分ける。

## 3. E0 — 反例の根拠を持つ検査

### 3.1 判定の構造

候補ごとに、契約の識別子、実物のコード、期待命題、証明の結果、反例、終了理由を記録する。候補の判定と検査処理の正常・異常を別の欄にする。

| 判定 | 必要な根拠 | 扱い |
| --- | --- | --- |
| `proved` | 実物に対応する、期待命題の閉じた定理と公理検査 | 必要な全契約について成立した候補だけ受理 |
| `counterexample` | 初期状態が契約を満たし、違反を再現する証拠 | どの性質の反例か、どのモデル／実機で確認したかを表示 |
| `unknown` | 証明も反例も得られていない理由 | 採用しない。タイムアウトや手順不足を誤実装の証明と数えない |
| `infrastructure_error` | 必須ファイル欠落、形式不正、結果の偽装、未処理例外等 | 当該の全体検査を失敗させる。通常の未知の候補に混ぜない |

「元の証明タクティックが例外を出した」を反例の根拠にしない。未対応の命令を研究候補として検出した場合は`unknown`、対応済みと宣言した必須の正例がデコードできない場合は段階未達または基盤異常として調査する。

### 3.2 最初に用意する事例

| 事例 | 初期状態と、確認する違反 |
| --- | --- |
| 戻り値の破壊 | 非ゼロの`dst`、`n=0`から誤った戻り値を得る |
| 保存レジスタの破壊 | `n=0`、壊されるレジスタに書き換え後と異なる値を置き、フレーム違反を確認 |
| 既存の終了条件の破壊 | `n=1`等から余分な反復による範囲違反を示す。元のラベルだけを根拠に非終了とは呼ばない |
| 読み過ぎ・書き過ぎ | `n=1`から1バイト先のアクセスを再生し、指定範囲外であることを確認 |
| 短い長さでの高速経路 | 整列したアドレスと`n=4`から8バイトアクセスの違反を示す。実機では番兵も使う |
| 明確な非終了 | ゼロ長で到達する`ret`を自己分岐に変え、異なる戻り先へ到達しないことを示す |
| 意味を保つ変形 | ゼロ代入を同じ意味の別命令へ変える等の正例を、元の公開契約で別に証明する |
| 契約外の入力 | 非重複等を満たさない入力を、公開契約の反例として受け付けない |

有限実行の反例は、コードとデータを配置した初期状態、命令の実行、違反条件をHOLで検査できる形にする。状態を作る際には、コードのロード、PC、引数、領域の非重複・非折り返しなど、元の前提も確認する。

自己分岐は、PCがその位置に留まる不変条件と戻り先の不一致から非到達を示す。実機のタイムアウトやランキング式の導出失敗を、非終了の証明にはしない。

ネイティブのガードページ試験は補助として維持する。ただし、8バイト整列した開始位置の4バイト後に通常のページ境界があるとは限らない。短い高速経路の違反は、モデル内の範囲検査と番兵で確認し、作れない配置のガードページ試験を要求しない。

**通過条件:** 既存の6種類の変更に少なくとも一つずつ具体的な違反の根拠があり、自己分岐の非到達と正しい変形の証明も得られる。既存版の履歴は上書きせず、新しい報告で証拠の種類を明確にする。

**検査自身の試験:** 必要な定理の欠落、開いた定理、違う命題、追加公理、期待バイトだけの更新、古い結果、例外後の継続、意図した`unknown`、基盤異常を分類できることを確認する。公理追加の試験は正常系と別プロセスへ隔離する。

## 4. E1 — 子の定理を使って親を組み立てる

### 4.1 部品の表現

OCaml内に、固定した命令の構造とブロックを置く。命令文字列だけを連結して定理名を付ける構成から、次の情報を照合する構成へ進める。

```text
Block = コードの定義
      + 事前・事後条件
      + 読み取り・書き込み範囲
      + 保存状態／変更レジスタ・フラグ
      + PC・コード配置の条件
      + イベントと終了の定理
      + 未解決の前提
```

これは実装上の項目であり、新しい実装公理ではない。ブロックを作る処理で、コード定義と定理の命題が対応していることを確認する。抽象型は取り違えを防ぐ補助とし、最終的な正しさはHOLの導出に委ねる。

命令本体と関数の`ret`を分ける。既存の「`ret`を含むオブジェクトの途中まで」の定理を、そのまま任意の連結に使えると仮定しない。部分列のロード、PCのずれ、コードと出力の非重複について補題を用意する。

### 4.2 小さい順に実装する

1. **Copy8の部品:** まず固定レジスタと固定オフセット0・8に限定する。実際の命令列の機能、フレーム、アクセス、終了を証明する。
2. **列の合成:** 二つをつないだCopy16を作る。子の事後条件から次の事前条件を導き、アクセス列とフレームを合成する。
3. **規模を一つ増やす:** オフセット16・24を加えたCopy32で同じ処理を再利用する。
4. **限定したレジスタの置換:** 一時レジスタを一つ差し替える。引数・戻り値・生きている値との衝突を拒否し、許可された変更範囲に収まる正例を証明する。
5. **分岐とループの接続:** E2に必要な入口の整列判定、残量の判定、ループ不変条件と減少量を受け取る合成処理を用意する。制御命令のステップの証明は行い、データ操作の部品内部は子の定理を使う。

ループ不変条件の自動発見や汎用のレジスタ割り当ては行わない。対象を広げる前に、固定した例の接続を通す。

### 4.3 直接記述との比較

同じレジスタ・命令選択・配置で、直接記述した版と合成した版を別に生成する。Copy16なら、例えば2組の64ビットロード／ストアと復帰の5命令を基準にする。命令本体の全バイトと長さを比較し、整列の余白も別に記録する。

親の証明は、子の定理と列・分岐・ループの規則から作る。子の全命令を再実行する処理へ別名を付けただけにしない。合成処理と親の証明をレビューし、使用した部品・規則・配置を報告する。その報告自体を、定理の代わりにはしない。

**通過条件:** Copy16とCopy32の両方で、直接記述版と全バイトが一致し、親のロード／ストアの再シミュレーションを子の定理へ置き換えられる。証明用の命令・データ・呼び出しが本体へ出ない。

**拒否する例:** 一時レジスタによる戻り値の破壊、フラグの不正な引き継ぎ、16バイトの親に8バイトしか権限を与えない例、2番目のブロックのずれ、コードと定理の取り違え、子の未充足条件の脱落。

## 5. E2 — 任意長の8バイトループ

### 5.1 APIと契約

実験用の名前を使い、既存の`vp_memcpy`を差し替えない。予定する主な宣言は次である。

```c
void *vp2_memcpy_chunk8(void *dst, const void *src, size_t n);
void *vp2_memset(void *dst, int c, size_t n);
```

埋め込みは既存のバイトループと同じ命令本体から始める。新しいコピーも、既存の`vp_copy_contract`と`vp_copy_access_contract`に相当する同じ契約を使う。定数名の違い以外で、前提・結果・変更範囲を弱めない。

特に、任意の有効な`size_t`、非NULL、非折り返し、非重複、通常RAM、排他的な更新、コードと出力の非重複を維持する。`n=0`ではデータアクセスなし、戻り値は元の`dst`。コピーの一時状態の変更は既存と同じX3・X4と許可したフラグ等に収め、引数レジスタを勝手に変更可能にしない。

### 5.2 実装と不変条件

両アドレスが8バイト整列していれば、`remaining >= 8`の間は8バイトずつ処理し、残り0〜7バイトをバイト処理する。未整列なら基本版へ進む。最初の版では、両アドレスをそろえるための先頭の処理や、未整列の64ビットアクセスは追加しない。

X3に処理済み長さ`i`を持ち、X4を残量の一時計算とロード値に使う構成を最初の候補とする。残量を毎回計算することで、元の引数・変更範囲を維持する。採用前に、対象のアドレス指定・命令のデコードを小さなオブジェクトで確認する。

主な不変条件は次とする。

- `0 <= i <= n`で、次の8バイト処理には`8 <= n-i`がある。
- 出力の先頭`i`バイトが開始時の入力と一致し、未処理の入力が保存される。
- ワード処理の間は`i`が8の倍数であり、両アドレスの整列が維持される。
- すべての中間の読み書きが入力・出力範囲内にあり、コード・保存レジスタ・SPを壊さない。
- 残量が減少し、端数処理も終了する。`i+8`等の機械語の計算が折り返さない。

**必須の定理:** 機能・終了・保存、アクセス範囲、ゼロ長、整列ガードと経路選択。ワード処理も元のバイト仕様へ結びつける。固定長や試験範囲だけの証明で代用しない。

## 6. 実物と試験

M1の各公開カーネルは、既存と同じく1関数1オブジェクト、コード再配置・外部呼び出し・定数表なしに限定する。合成用のラベルや部品の境界も、出力バイトと証明の配置へ対応させる。

1. 実際のオブジェクトを証明へ取り込み、命令バイトとの対応を確認する。
2. Cハーネスへリンクし、対象関数の開始から終了までを照合する。LLVMの位置表示とも対照する。
3. ソース・生成物・依存・期待命題を実行記録へ結びつけ、検査中に変化したら中断する。
4. 成功した成果物だけをネイティブ試験・測定へ進める。安全に隔離した破壊試験は別に行う。

| 試験 | 対象 |
| --- | --- |
| 境界長 | 既存の長さ集合に加え、0・8・16・32・64・256・4096それぞれからの端数0〜7、およびページ境界付近 |
| 整列 | コピーの入力・出力それぞれの8通りのずれ。ゼロ長・整列・未整列の経路 |
| 内容と保存 | 独立したCの参照結果、システムlibc、戻り値、入力、出力前後の番兵、負の埋め込み値 |
| ガードページ | 先頭・末尾に接する有効領域。複数ページの長さも必要に応じて用意する |
| ABI | Apple ABIの保存レジスタ、SP、復帰。カーネルにスタック・ヒープ操作がないこと |
| モデルの端 | 実機で配置しにくい大きなアドレス、最大値付近の計算、非折り返しの境界 |
| 破壊 | 8未満でのワードアクセス、最後のブロックの余分なアクセス、端数の欠落、戻り値・フレーム・減少量の破壊 |

契約に違反するNULL、重複、折り返しの呼び出しを通常のカーネル試験として実機へ渡さない。これらは、前提の不成立の検査やM2の検査付き呼び出し元で扱う。

## 7. 評価方法を実装結果を見る前に固定する

### 7.1 実行速度と容量

同じハーネスで、既存の基本版、長さ8専用版、発展版の8バイトループ、システムlibcを測り直す。過去の別実行のns値を、そのまま新しい測定との比較に使わない。

- 性能の長さ集合は既存の集合と、4096、32768、1MiBを基本とする。整列の組は少なくとも`(0,0),(1,0),(0,1),(1,1),(7,7)`を使う。全64通りの整列は正しさの試験で確保する。
- 各対象をウォームアップ後、独立したプロセスで少なくとも7回測る。順序は固定シードで入れ替え、中央値・最小最大・四分位点・生データを残す。
- 反復数は基本版で8ms以上を目安に調整し、同じケースの比較対象に同じ反復数を使う。大きな長さでは1回から調整し、固定の大量反復・大量ウォームアップで測定が不必要に膨らまないようにする。
- ウォームアップは転送量にも上限を設け、通常の試験・測定のバッファ総量は128MiB以下から開始する。実際の方法・反復数・上限を報告し、キャッシュが冷えているという保証には使わない。
- インライン化・呼び出し除去・builtin置換を避け、結果を観測する。逆アセンブルで呼び出しを確認する。
- 本体、整列余白、オブジェクト、同じハーネスの実行ファイルを分ける。容量比較用の実行ファイルは別ディレクトリの同じ出力名にし、署名識別子の差も混ぜない。

速度の判定は、中央値が比較対象の95%未満で、第3四分位が相手の第1四分位より小さい場合を「高速」、逆なら「低速」、それ以外は「不明」とする。統計的な信頼区間の保証とは呼ばない。

E2の性能仮説は、整列済み64・256・4096バイトの各ケースで基本版比の高速化が得られるかで評価する。長さ8専用版・libcとの比較や短い長さの退行も別に表示し、都合のよいケースだけで総合成功としない。

**必須の容量・資源条件:** 発展版で選択するコピーと埋め込みの本体合計256バイト以下、カーネルのスタック・ヒープ使用ゼロ、証明専用の実行コード・データゼロ。比較用の全実装の容量も別に記録する。

### 7.2 証明の再利用と修正負担

Copy16・Copy32の直接証明と合成の版について、少なくとも3回の新しい証明プロセスで、基盤のロード・部品の証明・親の証明の時間を分けて記録する。キャッシュの有無と依存を明記する。

オフセット一つの変更、一時レジスタの変更、部品の変更範囲の変更を同じ手順で行い、修正した箇所、手動のヒント、再検査対象、失敗理由を比較する。正しい変更と意図的に不正な変更を分ける。初回の操作時間は実験記録として残し、一般の開発者全体の効果へ一般化しない。

合成による親の再シミュレーションの除去と、同じ命令列の生成は必須条件とする。修正時間や証明時間の改善は、支持／未達／不明の評価とする。

## 8. M1の通過条件

1. 既存版の再現と、発展版への入力・出力の分離ができている。
2. E0の6種類の既存の変更、新しい自己分岐、正しい変形、契約外入力について、根拠を区別した結果がある。
3. Copy16・Copy32の親が子の定理を用いて証明され、直接記述と全バイトが一致する。
4. 任意長の8バイトコピーが、元と同じ機能・終了・保存・アクセスの契約を満たす。
5. 実際のリンク後の関数が証明対象と一致し、必要な境界・ABI・破壊試験が通る。
6. 容量・資源の必須条件を満たし、速度と修正負担の結果を未達も含めて保存した。
7. `verify-m1`と`measure-m1`、導入・再実行手順、前提の記録、M1の完了監査がある。

これを満たした後に、M1を完了としてM2へ進む。性能仮説が支持されなくても評価は完了できるが、証明の合成や必要な定理が欠けた状態を、測定結果の報告だけで完了にしない。
