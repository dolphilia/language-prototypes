# Tane（たね）0.1

[リポジトリの目次へ](../../README.md) · [試作言語の一覧へ](../README.md)

**自然数の変数と、4種類の文だけを持つ、小さなプログラミング言語の提案です。**

仕様、構文解析、実行器の理解しやすさを優先します。実行速度を求めないという
条件を使い、代入、四則演算、比較、条件分岐なども少数の操作の組み合わせで
表現します。既知のカウンタ計算モデルを、名前付き変数と構造化ループで
書けるように整理した設計です。計算モデルそのものの新規性は主張しません。

「絶対に最小」という主張はしません。仕様の短さ、処理系の短さ、
ソースコードの読みやすさでは最適な設計が異なるためです。

## 言語仕様

### 値と変数

- 値は自然数 `0, 1, 2, ...` のみ。桁数に仕様上の上限はありません。
- 変数名は `[a-z][a-z0-9_]*`。大文字は使用できません。
- 変数はすべて実行開始時に `0`。宣言は不要です。
- すべての変数はプログラム全体で共有します。スコープは1つです。

### 文

| 文 | 動作 |
| --- | --- |
| `inc x` | `x` を1増やす。 |
| `dec x` | `x` を1減らす。`0` の場合は `0` のまま。 |
| `while x` … `end` | `x` が `0` でない間、本体を繰り返す。毎回、本体の実行前に判定する。 |
| `print x` | `x` を10進数で標準出力に出し、改行する。 |

`end` はループ文の終端なので、文の種類は4つ、キーワードは5つです。
ループは入れ子にできます。最後の文に到達したら正常終了します。

標準機能は `print` だけです。モジュールの仕組みを設けず、組み込みの
出力関数として提供します。GUI機能はありません。

### 表記とエラー

- 1行に1文を書きます。`while x` と `end` もそれぞれ独立した行です。
- トークンは空白で区切ります。字下げと空行は意味を持ちません。
- `#` から行末まではコメントです。ソースファイルはUTF-8です。
- キーワードは小文字です。引数の位置ではキーワードも変数名にできます。
- 未知の命令、不正な引数、対応しない `while` / `end` は構文エラーです。
- 実行前にソース全体を検査します。構文エラー時には実行を開始しません。

数値リテラル、式、代入、関数、配列、文字列は最小仕様に含めません。
たとえば `3` は `inc x` を3回実行して作ります。

構文の骨格は次のとおりです。改行、空白、コメントの規則は上記に従います。

```text
program   := statement*
statement := "inc" name
           | "dec" name
           | "print" name
           | "while" name statement* "end"
```

## 実行例

```text
inc n
inc n
inc n

while n
    print n
    dec n
end
```

出力:

```text
3
2
1
```

加算も専用の演算子なしで書けます。`x = 2`, `y = 3` を準備した後、
次のコードで `x` は `5`、`y` は `0` になります。

```text
while y
    dec y
    inc x
end
print x
```

完全な初期化を含む例は [加算のサンプル](examples/add.tane)、二重ループで
`3 * 4` を計算する例は [乗算のサンプル](examples/multiply.tane) にあります。

## 計算能力を保てる理由

ここで「任意のロジックを書ける」は、時間と記憶容量の制限を理論上
外したとき、任意の計算可能な処理を表現できることとします。

自然数を保持し、増加、減少、ゼロ判定と制御の移動を行うレジスタ機械は
チューリング完全です。参考: David Doty,
[Lecture Notes for ECS 289A, 2.9.1–2.9.3](https://web.cs.ucdavis.edu/~doty/ecs289-2023/notes.pdf#page=35)。

Taneがその機械を模倣できる理由は次のとおりです。以下は本設計に対する
構成による説明であり、参考資料にTaneが登場するわけではありません。

1. `while x` の中で `dec x` を繰り返せば、変数をゼロにできます。
2. 元の変数から2つの作業変数へ1ずつ移し、一方から元へ戻せば、
   値を維持したコピーが作れます。作業変数は最初にゼロにします。
3. コピーをループ条件にし、ループ冒頭でそのコピーをゼロにすれば、
   「元の値が非ゼロのとき、本体を一度だけ実行」が作れます。
   別の変数を最初に1にして非ゼロの場合に消せば、ゼロ側の分岐も作れます。
4. レジスタ機械の各命令に「現在この命令か」と「次はこの命令か」の
   変数を1つずつ用意します。外側のループ内で現在の命令を一度実行し、
   次の命令の変数を1にします。走査後に次の変数群を現在の変数群へ移せば、
   任意のジャンプと停止を再現できます。

したがってレジスタ機械の各命令を有限個のTaneの文に置き換えられます。
専用の `if` や `goto` がなくても、計算能力は保たれます。

この説明では入力の自然数を、冒頭の `inc` の列などでプログラムに
埋め込みます。最小版には実行中の入力命令を設けていません。
実際の実行は、他の処理系と同様、利用可能なメモリや時間に制約されます。
計算能力の保証は、ファイル操作やネットワークなどの外部機能の提供を
意味しません。

## 処理系

参照実装は [tane.py](tane.py) の1ファイルで、Python 3の標準ライブラリだけを使います。

リポジトリルートから `prototypes/tane/` に移動して実行します。

```sh
cd prototypes/tane
python3 tane.py examples/countdown.tane
python3 tane.py examples/add.tane
python3 tane.py examples/multiply.tane
python3 -m unittest discover -s tests -v
```

実装は2段階です。

1. 各行を空白で分割し、命令を検査する。スタックで `while` と `end` を
   対応付け、命令列に飛び先を書き込む。
2. 命令番号と変数の辞書を持ち、命令列を順に実行する。

構文解析の再帰、演算子の優先順位、型推論、最適化、コード生成は不要です。
ここでの「コンパイル」は、この内部命令列への変換を指します。
解析時間はソース長に比例し、ループの対応付けも1回の走査で終わります。
実行中にループの終端を探し直す必要はありません。

自然数はPythonの多倍長整数を利用します。Python側に10進文字列への
変換桁数制限がある場合は解除し、`print` に固定の桁数上限を設けません。
実装の行数には、この多倍長整数や標準出力を担うPython本体は含みません。

## 設計上の代償と拡張の境界

小さくなるのは仕様と実行器です。利用側のプログラムは長くなり、
大きな値の初期化や計算は極端に遅くなります。数値だけの出力なので、
文字列をそのまま出す用途にも向いていません。

実用性を追加するときは、まず `set x 100` のような数値初期化、
次にコピー、加算などを検討できます。これらを既存の命令列に展開すれば
実行器の意味論を維持できますが、仕様と変換器の規模は増えます。
特に数値リテラルを `inc` に単純展開すると、短いソースから非常に長い
命令列を作るため、コンパイル速度とメモリ使用量には不利です。
その場合は即値命令を追加する設計との比較が必要になります。

外部入力や文字出力が必要になった場合も、計算部分を変えずにI/O命令を
追加できます。これらの拡張は0.1の仕様には含めません。
