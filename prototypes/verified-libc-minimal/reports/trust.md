# 保証の範囲と、残る信頼

通常のRAM、排他的な更新、非重複、非NULL、アドレス計算の非折り返し、コードと出力の
非重複という前提の下で、照合したAArch64命令列が公開契約を満たす。
試験した長さに制限せず、事前条件を満たす任意の`size_t`を扱う。

`ensures arm`は許した状態変更だけで後条件へ有限ステップで到達することを示す。
アクセス定理は逆順に蓄積するイベント列の新しく追加した部分を取り出し、範囲を確認する。
命令フェッチはこのデータイベントに含めない。CPU実時間、キャッシュ、投機実行、電力、
ページフォルトを含む実時間の上限は証明しない。

| 残る対象 | 扱い |
| --- | --- |
| 要求と形式仕様の対応 | 仕様を生成器と別ファイルで記述。Cの独立した参照結果、具体的な非空の呼び出し条件、境界試験で補助する。仕様の誤りを証明だけでは防げない |
| HOL Lightの論理・カーネル | 標準の無限性・選択・ηの3公理を使う。`check_axioms()`で追加を拒否し、期待命題と定理の空の仮定リストを確認する。信頼不要とは主張しない |
| OCamlと実行環境 | 5.1.0と全パッケージを固定。カーネルを動かすコンパイラ・ランタイムは信頼する。通常のソース読み込みを使い、HOLのモジュール構成は使わない |
| ISAモデル | s2n-bignumの固定コミットの意味が実機の対象動作と対応すると仮定する。モデルの完全性、CPU故障等は証明しない |
| Mach-Oの取り込み | s2n-bignumの処理でコードとリテラルを照合する。取り込み処理そのものは未検証 |
| リンク後の抽出 | 自作Pythonがセクション・ロード時の対応・シンボル・範囲・全バイトを検査し、LLVMの位置表示と対照する。検証済みリンカの定理ではない |
| 生成器・アセンブラ・リンカ | 誤ったコード出力を証明・バイト照合で検出する。Cハーネスのコンパイル、起動、ロードの正しさは別に仮定する |
| OS・権限・並行実行・ハードウェア | 入口の契約を維持すると仮定する。解放後の呼び出し、競合、MMIO、CPU故障等を扱わない |
| 試験・計測・集約 | 未検証。固定シード、独立した参照結果、改変試験、生データを残す。統計的な測定を形式証明として扱わない |

初期にPATHで見つかったClangは19.1.7だったが、実際のアセンブル・Cコンパイル・リンクは
`xcrun clang`（Apple Clang 17.0.0）へ統一した。HOL LightのC部品もApple SDKを明示して構築した。
依存と構成を通常の検査で自動更新しない。

実施した補助ツールはopam 2.4.1、Python 3.14.4、GNU Make 3.81。
具体的な依存コミットとOCamlパッケージは`deps.lock`と`opam-switch.export`を参照。

## 容量の読み方

命令本体とMach-O全体の容量は別に数える。同じCハーネスの`__text`は基本版340、
最適化版372バイトで、差はコピー本体の増分32バイトと一致する。
一方、`__TEXT`セグメント末尾のページ配置用の余白は14,884から14,852バイトへ減る。
オブジェクト内の対象関数の整列余白はどちらも0バイト。

実行ファイルは`size_scalar`と`size_optimized`という名前で出力したため、リンカの
ad-hoc署名のIdentifierも異なる。`codesign -dvv`が示すCodeDirectoryの容量は388と391バイト。
ファイル全体の差8バイトを命令本体の差として扱わない。
これらの構造は`xcrun llvm-objdump --macho --syms`、`codesign -dvv`、抽出ツールで再確認できる。

マクロに実装公理を登録する必要はなかった。実物のロード／ストアをモデルで実行し、
変更範囲とイベントを含む定理を添えられる。一方、ループ不変条件、配置、ABI、成果物の
対応は別の作業として残る。この版は任意の証明付きマクロを自動合成する新言語ではない。

証明やghost値は実行コードへ出ず、証明を付けること自体による命令数の増加はない。
今回増えた32バイトは高速経路と分岐である。8バイト以外では分岐が余分になる。
保証、抽象化、性能を別々に記録する必要がある。
