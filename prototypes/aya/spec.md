## 1. 設計の範囲

### 1.1 基本方針

Ayaは、静的に型付けされ、ネイティブ実装も可能な汎用言語として設計する。初版の中心は、次の組み合わせである。

| 要素 | Ayaでの位置づけ |
| --- | --- |
| 所有権 | 所有する値の移譲と破棄を追跡する |
| 可変値意味論 | 通常のデータは独立した値として扱い、その場で変更できる |
| 一時的な借用 | 値を複製せず、読み取りや排他的な変更の権限を渡す |
| モード | 局所性、クロージャの呼び出し方、移譲可能性を分けて検査する |
| ブランド付き領域 | 参照関係と変更権限を分け、循環する共有データを扱う |
| 効果とケイパビリティ | 行いうる操作と、その操作の対象への権限を分ける |
| 外部契約 | 検証していない外部の振る舞いについて、接続時の責任を記録する |

一般の第一級借用参照、継承、暗黙のユーザー定義変換、動的な型キャスト、任意の生ポインタ操作は0.1に含めない。

### 1.2 安全性の範囲

規則に従う内部コードについて、解放後使用、範囲外アクセス、未初期化値の読み取り、不正な型の値の生成、非同期の競合するメモリアクセスを防ぐことを目標とする。

外部契約を未検証の信頼として受け入れた構成では、その保証は外部契約の成立を前提とする。契約違反からも内部を守るには、検証済みの制約・隔離を持つ接続が必要になる。

計算結果の正しさ、終了、デッドロックの不在、メモリ使用量の上限、資源漏れの完全な不在、すべての副作用の適切さは、通常の型検査の保証に含めない。

### 1.3 初版で絞る範囲

ユーザー定義の一般的な破棄関数、async/await、効果ハンドラ、タスク間の可変グラフ共有、任意の命題を受け入れる`assume`、ユーザーによる安全性に関わる型特性の無検証な実装は含めない。

安全な基本操作の実装根拠を、処理系・ランタイムの検証計画として管理する。利用者へ万能の証明言語を要求する設計にはしない。

## 2. 字句と基本構文

### 2.1 ソースと名前

- ソースはUTF-8とする。識別子は0.1ではASCIIの`[A-Za-z_][A-Za-z0-9_]*`に限定する。
- コメントは`//`から行末、または入れ子を許さない`/* ... */`とする。
- 文の終端は`;`、ブロックは`{ ... }`とする。字下げと改行は意味を持たない。
- 型名、関数名、モジュール名は大文字小文字を区別する。
- パスは`std::vec::push`のように`::`で区切る。`.`はフィールドの選択に使う。
- モジュールのトップレベルに実行文は置かない。実行時の可変なグローバル変数は禁止する。

予約語は、本書の文法で文字列として示す語とする。`read`、`inout`、`take`、`init`、`move`、`domain`、`local`、`view`、`yield`、`scope`、`unsafe`を含む。

### 2.2 リテラルと評価

整数リテラルは10進、または`0x`で始まる16進とする。`10i64`、`10u8`などの型接尾辞を認める。文脈で型が決まらない整数は`I64`とする。文字列はUTF-8の内容を持ち、`"`、`\`、改行、タブのエスケープを認める。

浮動小数点リテラルは小数点を持つ10進数とし、型が決まらなければF64とする。`true`・`false`、`()`をリテラルとして持つ。Charリテラルは一つのUnicodeスカラー値を単引用符で囲む。型に収まらない定数はコンパイル時に拒否する。

実行時のStringリテラルは、所有するStringの構築として`alloc`・`panic`の上限を持つ。契約宣言や接続設定の文字列はコンパイル・配備時のメタデータであり、実行時の式ではない。

式と引数は左から右へ評価する。`&&`、`||`は短絡評価する。代入は右辺を評価してから左辺の既存の内容を破棄し、置き換える。右辺の評価中も、既存の借用制約を守らなければならない。

### 2.3 文と制御

`let`、`var`、代入、関数呼び出し、`if`、`while`、`match`、`return`、`break`、`continue`を持つ。`if`と`match`は式としても使える。結果を返す関数は、すべての正常終了経路で`return`する。ブロック末尾の式による暗黙のreturnは設けない。

```aya
fn abs(read n: I64) -> I64 !{panic} {
    if n < 0 {
        return -n;
    }
    return n;
}
```

`I64`の最小値の符号反転はオーバーフローであるため、この例には`panic`効果がある。

## 3. 型と値と資源

### 3.1 組み込み型

| 型 | 意味 |
| --- | --- |
| `Unit`、`Bool` | 単位値`()`と真偽値 |
| `I8`〜`I64`、`U8`〜`U64` | 指定ビット幅の整数 |
| `Usize` | 対象のアドレス幅の符号なし整数。32または64ビット |
| `F32`、`F64` | IEEE 754に従う浮動小数点数 |
| `Char`、`String` | Unicodeスカラー値とUTF-8文字列 |
| `(T, U)`、`[T; N]` | タプルと固定長配列 |
| `Vec<T>`、`Box<T>` | 所有する可変長配列と、所有する間接格納 |
| `Option<T>`、`Result<T, E>` | 省略可能な値と、成功または失敗 |

`Bytes`は`Vec<U8>`の型別名とする。null値は持たない。再帰型は`Box`、`Vec`など、大きさが有限になる間接格納を介さなければならない。

### 3.2 構造体と列挙型

```aya
struct Point {
    x: I64,
    y: I64,
}

enum Shape {
    Empty,
    Circle { radius: U64 },
    Pair { left: Box<Shape>, right: Box<Shape> },
}
```

フィールドは宣言したモジュール内だけで直接アクセスできる。`pub`を付けたフィールドは公開される。`match`はすべてのvariantを扱うか、最後に`_`を持たなければならない。

variantは、フィールドなしの`None`、位置付きの`Some(T)`、名前付きの`Circle { radius: U64 }`の形を持てる。構築とパターンは対応する同じ形を使う。構築する既存の非Copyフィールド値には`move`を要求する。

`match`は所有する式を対象とする。既存の非Copy値を分解するには`match move x`と書く。パターンが束縛した部分は、その分岐の所有値となり、束縛しない部分は終了する。読み取りから非Copy値を分解したい場合は、通常のフィールド投影か、明示的なcopyを使う。借用パターンの一般化は0.1に含めない。

### 3.3 型の構造的な性質

以下は、処理系が組み込み型とフィールドの構成から計算する特性である。ユーザーは無検証な`impl`で付け足せない。

| 特性 | 意味 |
| --- | --- |
| `Value` | 内部に観察可能な共有可変状態や外部資源の同一性を持たない |
| `Copy` | 値の文脈で暗黙に複製してよい |
| `Send` | 所有を別タスクへ移譲してよい |
| `Sync` | 読み取り権限を複数タスクで共有してよい |

整数などのスカラー、`Unit`、`Bool`は四つを満たす。通常の構造体・列挙型・タプルは、対応する特性を全フィールドが満たすときにその特性を満たす。ただし、動的な所有格納を持つ`String`、`Vec`、`Box`は`Copy`ではない。

`Vec<T>`と`Box<T>`は、`T`が満たすとき`Value`、`Send`、`Sync`を満たす。関数値の特性は9節、共有領域の型は8節、外部資源の型は13節に従う。

### 3.4 値意味論

`Value`を満たす値を`copy`で複製したとき、複製直後の内容は同じであり、その後の片方の変更は他方へ影響してはならない。

```aya
var a = [1i64, 2i64, 3i64];
var b = copy(a);
b[0] = 9;
assert(a[0] == 1);
```

この配列リテラルは`[I64; 3]`であり`Copy`でもある。動的な配列も`copy`で独立した値にできるが、暗黙には複製しない。

`copy(read x: T) -> T`は`T: Value`に限る組み込み操作である。ユーザー定義のコピー実装は0.1では認めず、構造に従った複製を処理系が提供する。Copyな型の複製の効果は空とし、それ以外のValueの複製には保守的に`alloc`・`panic`を要求する。

Copy-on-Writeやコピーの除去は、この意味を変えない範囲で許す。記憶領域の同一性を、`Value`の通常のAPIから観察できるようにしてはならない。

最適化は、宣言した効果の保証も保たなければならない。CoWの遅延複製によって、allocを許さない変更操作へ新しい割り当てやその失敗を持ち込む実装は不可である。初期の参照実装は、動的なValueをcopy時に複製する方式を基準とする。

### 3.5 同一性を持つ資源

`resource struct`は、フィールドが整数だけでも、`Value`と`Copy`を満たさない。

```aya
resource struct RequestId {
    raw: U64,
}
```

共有領域のセルハンドル、権限キー、外部接続、タスクハンドルなども、通常の値意味論とは区別する。特に`Copy`であるハンドルを複製しても、対象のデータを複製したことにはならない。`Copy`は`Value`を含意しない。

## 4. 所有と初期化

### 4.1 束縛

- `let x = e;`は、所有する値の再代入不可の束縛を作る。
- `var x = e;`は、所有する値を変更できる束縛を作る。
- `var x: T;`は、未初期化の格納先を作る。初期化前に読んではならない。
- 借用を保持する束縛は`read x = e;`または`edit x = e;`とし、6節の制約を受ける。

`let`は所有権の移譲まで禁止するものではない。所有する値の生存期間を、最後の読み取り時点だけで自動的に終了させてはならない。早期の破棄には`drop`を使う。

### 4.2 複製と移譲を区別する

`Copy`な値を、所有する値が必要な文脈で使うと暗黙に複製する。それ以外の既存の所有値を渡すには、`move x`を明記する。

```aya
var a = vec::from_array([1i64, 2i64]);
let b = move a;
// let n = vec::len(a);  // 拒否: aは移譲済み

var c = copy(b);
vec::push(&c, 3);
```

所有する一時値は、`move`なしで受け渡せる。`move x`を明記した場合は、`Copy`な型でもその束縛を消費する。

### 4.3 状態の追跡

処理系は各格納先・フィールドを、少なくとも`未初期化`、`初期化済み`、`移譲済み`として追跡する。分岐の合流後に読むには、到達するすべての経路で初期化済みでなければならない。

フィールド単位の移譲を認めるが、部分的に移譲された構造体を全体として読んだり渡したりしてはならない。破棄時には、初期化済みの部分だけを処理する。

### 4.4 破棄

正常なスコープ終了、`return`、`?`による脱出、代入による置き換え、`drop(move x)`で、対象の初期化済み部分を一度だけ破棄する。局所変数は宣言の逆順、構造体のフィールドは宣言順に破棄する。

0.1は、ユーザー定義の破棄関数を持たない。通常の値は構造的に破棄し、標準の資源型は仕様で定める終了処理を持つ。型`T`の終了処理に効果`final(T)`があるなら、その終了が起こりうる関数の効果上限へ含める。内部の記憶領域の解放だけなら`final(T) = {}`とする。

`final(T)`は処理系が算出する効果の集合であり、効果上限へ`!{final(T)}`の形で記述できる。構造体・enum・Vec・Boxの終了効果は、保持しうる構成要素の終了効果の上限の和集合とする。一般の型引数へも、この項を保持する。所有を結果へ完全に移譲した経路で、その所有値の終了効果を重ねて要求する必要はない。

通常の所有はアフィン的であり、値を使わずに終了させることも認める。「必ず一回使う」という一般的な線形型の規則は設けない。

メモリ安全性を、終了処理が必ず実行されることだけに依存させてはならない。異常停止や外部操作の未完了がある場合の資源の扱いは、15節と13節に従う。

## 5. 関数とアクセス規約

### 5.1 宣言

```aya
fn shift(inout p: Point, read delta: I64) -> Unit !{panic} {
    p.x += delta;
}
```

引数名の前にアクセス規約を書く。省略時は`read`とする。戻り型の省略は`Unit`、戻り値の省略は`return ();`と同じとする。

| 規約 | 呼び出し側の表記 | 関数内の権限 | 正常終了時の条件 |
| --- | --- | --- | --- |
| `read` | `f(x)` | 一時的に読む。所有を受け取らない | 元の値を維持する |
| `inout` | `f(&x)` | 初期化済みの格納先を排他的に変更する | 全体を初期化済みに戻す |
| `take` | `f(move x)` | 所有を受け取る | 元の格納先は消費済み |
| `init` | `f(&x)` | 未初期化の格納先を初期化する | 全体を初期化済みにする |

`take`で受け取った束縛は、通常の`let`と同じく、そのままでは変更できない。変更には新しい`var`へ移す。

### 5.2 呼び出し境界

`read`引数は、呼び出し中、重なる経路から変更されてはならない。`inout`と`init`の対象には、その期間、重なる他のアクセスを認めない。

```aya
fn add(inout target: I64, read amount: I64) -> Unit !{panic} {
    target += amount;
}

var n = 5i64;
// add(&n, n);  // 拒否: 同じ格納先を変更用と読み取り用へ渡す
let old = n;
add(&n, old);
```

引数を左から評価し、作った借用は呼び出しが終わるまで保持する。後の引数を評価する際も、先に作った借用を尊重する。`Copy`な型でも、`read`引数の格納先を自動で別の一時値へ置き換え、競合を隠してはならない。

`read`は渡した値の観察・アクセス規約であり、資源ハンドルの指す全状態を不変にする指定ではない。Valueな値については独立した内容を保ち、CellRefなどの資源については、対象の内容へ触れるための追加の権限を別に要求する。

### 5.3 所有する戻り値

普通の関数の戻り値は所有する値である。`read`引数から所有値を返すには、`Copy`による複製または`copy`が必要になる。借用を返すには、6節の`view`を使う。

### 5.4 初期化と途中での移譲

`init`と`inout`は、正常なすべての出口で初期化条件を満たす。`Result::Err`や`?`も正常な出口であり、例外ではない。

```aya
fn origin(init out: Point) -> Unit !{} {
    out = Point { x: 0, y: 0 };
}

var p: Point;
origin(&p);
```

失敗時に出力を作らない関数は、`init`ではなく`Result<T, E>`を返す形式にする。`inout`内で値を移譲して一時的に空にすることは許すが、戻る前に再初期化しなければならない。

## 6. 借用と投影

### 6.1 一時的なアクセス経路

```aya
var p = Point { x: 1, y: 2 };
edit x = p.x;
x = 9;
assert(p.x == 9);  // xの利用が終わった後
```

`read`・`edit`束縛は、値の複製でも、自由に保存できる参照値でもない。`read`は共有読み取り、`edit`は排他的な変更の投影を作る。

editの利用を終了するとき、対象の格納先を全体として初期化済みに戻さなければならない。再借用している間は、親の投影の重なる利用を止める。親子関係に従う再借用を、互いに独立した二つの排他権限として扱ってはならない。

投影は、通常の構造体・配列・戻り値の所有フィールドへ保存できない。投影を捕捉したクロージャは局所的な値となり、その借用期間を越えて保持できない。

### 6.2 借用期間と競合

借用期間は、制御フロー上で投影とその再借用を使用する範囲から求める。所有値の破棄時点と、借用が終わる時点は別である。

静的に異なるフィールドは、重ならないものとして扱う。動的な添字は、定数や既知の不等関係から証明できない限り重なる可能性があると扱う。拒否されたとき、暗黙に実行時の借用検査へ切り替えない。

```aya
edit x = p.x;
edit y = p.y;
x = 10;
y = 20;  // 受理: 異なるフィールド
```

### 6.3 ユーザー定義のview

```aya
view smaller(inout a: I64, inout b: I64) -> inout I64 !{} {
    if a < b {
        yield &a;
    } else {
        yield &b;
    }
}

var a = 4i64;
var b = 2i64;
edit selected = smaller(&a, &b);
selected = 12;
assert(b == 12);
```

`view`の結果規約は`read`または`inout`とする。各正常経路で一度だけ`yield`し、投影の使用終了後に残りの処理へ戻る。投影の間は呼び出しフレームを保持する。

投影先は、引数から許可された格納先、または8節のセル操作で得た対象に限る。view内の一時的な所有値を、外へ投影してはならない。

0.1では、viewのすべてのアクセス引数を、投影の最後の使用まで借用する。上の例は、選ばれなかった側もその期間借用する。別コンパイル時に、関数本体を見て勝手に制約を緩めない。

投影の終了時にviewの後続処理を実行し、それが正常終了してから引数の借用を解放する。利用側の正常な`return`・`?`・`break`でも同じ処理を行う。後続処理の効果もviewの効果上限に含める。panic時の終了処理は15節に従う。

### 6.4 安全な範囲分割

`vec::with_split`は、境界を検査した上で、前半・後半を重ならない一時的な`Span<T>`としてコールバックへ渡す標準機能とする。`Span<T>`は所有できず、`read`・`inout`引数と局所的な投影にだけ現れる。

このような分割は、検査済みの標準基本操作が作る証拠に基づく。任意の注釈で二つの領域を非重複と宣言することは認めない。

## 7. 局所性とモード

### 7.1 三つの問いを分ける

| 問い | 表現 | 既定の方針 |
| --- | --- | --- |
| 現在の領域から持ち出せるか | `local`と領域依存の追跡 | 所有値は持ち出せる。借用・ブランド依存は制限される |
| クロージャをどう呼べるか | `many`、`mut`、`once` | 捕捉と本体から推論する |
| 別タスクへ渡せるか | `Send`、読み取り共有には`Sync` | 型の構造と捕捉から計算する |

所有値の一意性は4〜6節で扱い、別の`unique`注釈を重ねない。`Send`と`Sync`は0.1では構造的な特性として実現する。これらの表現がOxCamlの各モードと一対一に対応するとは定めない。

### 7.2 局所割り当て

`local`を付けた所有束縛では、その値の所有する新規格納を現在の領域へ置く。処理系は、スタックまたはスコープ付きアリーナで実現できる。単なる最適化の希望ではなく、持ち出し制約を伴う。

```aya
fn total() -> I64 !{alloc, panic} {
    local let xs = vec::from_array([1i64, 2i64, 3i64]);
    return xs[0] + xs[1] + xs[2];
}
```

上では、要素の整数が記憶領域に依存しないため、整数の複製を返せる。`return move xs;`は拒否する。`T: Value`なら、`copy(xs)`で独立した通常の所有値を作って返せる。

普通の`copy`の動的な格納先は、持ち出せる通常のヒープとする。局所値を無条件に持ち出せるようにするモード変換は持たない。

### 7.3 局所性は、捕捉や入れ子の値にも伝わる

ある領域の格納、投影、ブランドに依存する値を含むなら、コンテナやクロージャもその依存を持つ。型パラメータや非公開フィールドへ隠しても依存は消えない。

ただし、`Share<T>`のように、独立した生存期間の格納を持つ型の内容は、その型の仕様に従う。外側の一時的なラッパーが局所的であることだけで、内容の生存期間まで短くしたり長くしたりしてはならない。

### 7.4 公開インターフェース

公開関数では、型とアクセス規約に加え、局所的な引数を受け取る所有スロットに`@local`を指定できる。

```aya
fn consume_local(take xs: Vec<I64> @local) -> Usize !{} {
    return vec::len(xs);
}
```

規範的な条件は、引数の依存領域を結果や長く生きる格納へ逃がしてはならないことである。`take ... @local`は通常の持ち出せる所有値も受け入れるが、依存領域がある可能性を前提に検査する。`read`・`inout`・`init`引数には、そもそも呼び出しを越えて保持しない規約が適用される。

公開関数が返す通常の所有値には、引数の一時的な借用への依存を含めてはならない。ブランドを含む所有ハンドルは、明示したブランド型引数に従う。

通常の所有スロットが要求する持ち出し可能性は、明示されたブランド依存の生存範囲内で判定する。`CellRef<d, T>`を通常のtake引数へ渡すことまで禁止する意味ではない。その依存は結果や格納にも残り、dの外へは持ち出せない。

## 8. 共有する領域

### 8.1 領域、セル、キー

```aya
domain d as (arena, key) {
    let a = arena::alloc(&arena, 10i64);
    let b = arena::alloc(&arena, 20i64);
    read x = cell::read(a, key);
    read y = cell::read(b, key);
    assert(x + y == 30);
}
```

`domain`は、その実行ごとに新しい不変のブランド`d`を生成し、変更可能な束縛として`Arena<d>`と`Key<d>`を作る。Arenaは領域の固定した所有者であり、借用だけを許し、移譲・明示破棄を禁止する。

Keyは、その領域の生存範囲内で通常のアフィンな資源として移譲・破棄できるが、複製も領域外への持ち出しもできない。Keyを破棄してもセルを回収せず、そのキーによる以後のアクセスができなくなる。

| 型 | 役割 | 主な特性 |
| --- | --- | --- |
| `Arena<d>` | セルの格納を所有する | `Value`・`Copy`・`Send`・`Sync`ではない |
| `Key<d>` | セル群の内容へアクセスする権限 | `Value`・`Copy`・`Send`・`Sync`ではない |
| `CellRef<d, T>` | 領域内のセルを指すハンドル | `Copy`だが`Value`・`Send`・`Sync`ではない |

キーはセルを所有せず、アリーナは内容への権限キーではない。キーを借りることと、アリーナの生存期間を分ける。

### 8.2 操作の規則

- `arena::alloc(&arena, value)`は値の所有を受け取り、セルを領域へ格納する。`alloc`効果を持つ。
- `cell::read(cell, key)`は、ブランドが一致するセルとキーを共有借用し、内容の読み取り投影を作る。
- `cell::write(cell, &key)`は、ブランドが一致するキーを排他的に借用し、内容の変更投影を作る。
- 投影を使う期間、対応するキーの借用を保持する。
- ブランドの同一視、短縮、型変換は禁止する。別のdomainのキーを使ってはならない。

同じキーの読み取り投影を複数作ることはできる。変更投影が有効な間は、同じキーから別の読み取り・変更投影を作れない。異なるセルでもこの制約を受ける。

### 8.3 メモリと領域の終了

セルの格納先は、追加の割り当てによって移動してはならない。0.1は個別のセル削除・解放を認めず、domainの終了時に一括回収する。

セルに入れた内容は、domainの終了まで有効でなければならない。より短い借用・局所領域への依存を格納してはならない。セル内に、同じdomainのセルハンドルや、より長く生きる外側domainのハンドルを格納することはできる。

domain終了時は、すべての投影を終了し、セルの内容を割り当ての逆順に一度だけ破棄してから格納を回収する。ハンドルの破棄は対象をたどらないため、循環によって再帰的な二重解放は起こさない。

セルへ格納する型Tの終了効果は、保守的にalloc操作の効果へ`final(T)`として加える。このため、呼び出し先から外側のdomainへ格納する場合も、その終了に必要な効果をインターフェースから消せない。

domainのブランドを含む値・クロージャ・隠れた依存を外へ持ち出すことは禁止する。参照を含まない整数や、`Value`を複製した結果は持ち出せる。

### 8.4 循環グラフ

```aya
resource struct Node<brand d> {
    value: I64,
    next: Option<CellRef<d, Node<d>>>,
}

fn graph_sum() -> I64 !{alloc, panic} {
    var result = 0i64;
    domain d as (arena, key) {
        let a = arena::alloc(&arena, Node<d> { value: 10, next: None });
        let b = arena::alloc(&arena, Node<d> { value: 20, next: Some(a) });
        {
            edit node = cell::write(a, &key);
            node.next = Some(b);
        }
        read left = cell::read(a, key);
        read right = cell::read(b, key);
        result = left.value + right.value;
    }
    return result;
}
```

`Node`は共有の同一性を含むため、通常の独立した値としてコピーしない。この領域だけで共有可変状態を明示する。領域全体の複製は、ハンドルを対応付け直す別のアルゴリズムとして実装する。

0.1では同じキーによる複数セルの同時変更や、キーの分割を標準機能に含めない。逐次的な変更か、別domainへの分割で記述する。

## 9. 関数値とジェネリクス

### 9.1 クロージャの捕捉

```aya
let offset = 3i64;
let add_offset = fn [read offset] (read x: I64) -> I64 !{panic} {
    return x + offset;
};
```

捕捉は`read`、`inout`、`take`を明記する。捕捉省略リストによる暗黙の環境取得は0.1に含めない。グローバルな可変状態の暗黙取得も認めない。

`read`・`inout`捕捉は借用であり、その依存をクロージャへ伝える。`take`捕捉は所有の移譲である。所有を捕捉したことだけでは、クロージャが一回しか呼べないとは限らない。

### 9.2 呼び出しモード

| モード | 呼び出し方 | 本体の制約 |
| --- | --- | --- |
| `many` | `f(args)` | 捕捉状態を読むだけ。所有する捕捉を消費しない |
| `mut` | `(&f)(args)` | 捕捉状態を変更できる。呼び出し間には有効な状態へ戻す |
| `once` | `(move f)(args)` | クロージャを消費し、捕捉の所有を移譲できる |

推論では、消費があれば`once`、なければ変更があると`mut`、それ以外は`many`とする。`many`を`mut`または`once`の要求に、`mut`を`once`の要求に利用できる。逆は不可である。

型は`fn many(read T) -> U !E`のように表す。呼び出しモードと、クロージャの複製可能性は別である。クロージャ自体を暗黙に`Copy`とはしない。

関数値の型・モード情報は、表示した呼び出し型に加え、捕捉の領域依存と終了効果を保持する。所有する関数値を引数・フィールドなどへ抽象化しても、その情報を消してはならない。終了効果の上限は所有スロットに`@final{...}`で指定でき、指定のない所有スロットは空の終了効果を要求する。readスロットは対象を破棄しないので、その制限を課さない。

onceとして消費して呼ぶときは、呼び出し効果に加え、残る捕捉の終了効果も計上する。manyやmutからonceへ変換しても、その終了効果を消してはならない。関数値を呼ばずに破棄する場合は、捕捉の終了効果だけを計上する。

### 9.3 型の特性と捕捉

クロージャを`Send`とするには、所有する捕捉がすべて`Send`であり、他タスクへ持ち出せない投影やdomain依存を含まないことが必要である。共有読み取りの捕捉をタスクへ持ち出す機能は0.1では認めない。

借用捕捉のあるクロージャはSend・Syncではない。所有捕捉だけのクロージャは、そのすべてがSyncならSyncである。ただし、mutの呼び出しに排他的な権限が必要な規則は変わらない。捕捉のない通常の関数値はValue・Send・Syncである。

`Value`な所有捕捉だけを持つクロージャは、捕捉内容も独立に複製できる場合に限り`Value`とする。権限キーや接続を捕捉したクロージャを、単に不変であるという理由で`Value`にしてはならない。

### 9.4 型引数とtrait

ジェネリクスは静的な型引数、ブランド引数、効果引数を持つ。型引数は大文字、ブランドと効果引数は宣言位置の`brand`・`effect`で区別する。

```aya
trait Equal {
    fn equal(read a: Self, read b: Self) -> Bool !{};
}

fn same<T: Equal>(read a: T, read b: T) -> Bool !{} {
    return Equal::equal(a, b);
}
```

traitの実装は、型またはtraitを定義したモジュールに限る。同じ型とtraitの組に複数の実装を認めない。動的なtraitオブジェクト、特殊化、任意の存在型は0.1に含めない。

ブランドの利用箇所では、8節のように`Node<d>`と書ける。構造体や関数の型パラメータの宣言では、`Node<brand d>`や`fn read_node<brand d>(...)`のように種類を明示する。

## 10. 効果と制御

### 10.1 効果の集合

関数型の`!{...}`は、その関数の実行と、その関数内の終了処理が起こしうる効果の上限である。

| 効果 | 意味 |
| --- | --- |
| `alloc` | 新しい動的格納を要求する |
| `panic` | 検査失敗などによりプログラムを異常停止しうる |
| `io` | 標準サービスを通じた外部I/Oを行う |
| `spawn` | 子タスクを作る |
| `wait` | 他の処理の進行を待ち、ブロックしうる |
| `external(C)` | 外部契約`C`に属する操作を行う |

局所変数や`inout`引数の変更は、アクセス規約で表し、別の汎用的な`state`効果を要求しない。したがって`!{}`は、副作用を持たない数学的な純粋関数という意味ではない。

`external(C)`だけでは`io`や`wait`を包含しない。外部操作のプロファイルが指定する上限を、すべて加える。効果の宣言だけで外部を操作できるわけではなく、対応する権限も必要である。

### 10.2 推論と包含

非公開関数は効果上限を省略でき、その本体から推論する。公開関数は明記する。実際に要求される効果の集合が宣言した上限の部分集合でない場合、拒否する。

効果の少ない関数を、効果上限の大きい関数スロットへ渡せる。逆は不可である。`effect e`を効果変数として宣言し、`!{alloc, panic | e}`のように集合を拡張できる。

`final(T)`のように型へ依存する効果の項も、型引数が決まるまで保持する。通常の効果と同様に、集合の包含として検査する。

```aya
fn apply<T, U, effect e>(read x: T, f: fn many(read T) -> U !e) -> U !e {
    return f(x);
}
```

この例の`f`は、デフォルトの`read`引数である。関数値が捕捉している借用や資源も、型・モード検査の対象となる。

### 10.3 エラー

回復可能な失敗は`Result<T, E>`で表す。`e?`は、`Ok(v)`なら所有する`v`を式の結果とし、`Err(e)`なら同じエラー型の`Err(e)`を返す。暗黙のエラー型変換は行わない。

`?`で脱出する際も通常の終了処理を行い、`init`・`inout`の出口条件を満たす。捕捉可能な例外やスタック巻き戻しは0.1に含めない。

### 10.4 panicと基本演算

整数の通常の四則演算は、全ビルドでオーバーフロー、ゼロ除算、範囲外の除算を検査し、失敗時は`panic`とする。`wrapping_*`と`checked_*`は明示的な標準関数とする。

配列・Vec・Spanの`[i]`は境界を検査し、失敗時は`panic`する。失敗を値で扱いたければ標準の検査付きアクセスを使う。`panic`効果を消すには、処理系が検査条件を静的に証明するか、失敗しない別のAPIへ書き換える。最適化を有効にしただけで検査を外してはならない。

動的な格納の取得に失敗した場合は、組み込みの割り当て器は`panic`する。そのため、動的な構築を行うAPIは通常`alloc`と`panic`の両方を持つ。`panic`はプロセス全体を終了し、終了処理の実行は保証しない。

## 11. タスクと共有

### 11.1 構造化されたタスク

`scope s { ... }`は、そのスコープ内で子タスクを作る実行領域を作る。`s`は変更可能な組み込みのスコープ権限であり、複製・持ち出し・明示破棄はできない。

```aya
fn parallel_total(take left: Vec<I64>, take right: Vec<I64>)
    -> I64 !{alloc, spawn, wait, panic} {
    var result = 0i64;
    scope s {
        let a = task::spawn(&s,
            fn [take left] () -> I64 !{panic} {
                return sum(left);
            });
        let b = task::spawn(&s,
            fn [take right] () -> I64 !{panic} {
                return sum(right);
            });
        let x = task::join(move a);
        let y = task::join(move b);
        result = x + y;
    }
    return result;
}
```

この例で使用するsumは、次のように定義できる。

```aya
fn sum(read xs: Vec<I64>) -> I64 !{panic} {
    var total = 0i64;
    var i = 0usize;
    while i < vec::len(xs) {
        total += xs[i];
        i += 1;
    }
    return total;
}
```

捕捉したVecは子タスク内で所有され、読み取りに使った後に破棄される。捕捉内容を消費しないので、このクロージャは`many`でもよく、spawn側で`once`として受け取る。

### 11.2 移譲と終了

子タスクへ渡す所有捕捉と、その結果型は`Send`であり、親の投影・局所格納・domainブランドへ依存してはならない。タスクハンドルは`Task<s, T, E>`であり、`Copy`・`Value`・`Send`・`Sync`ではない。

`task::spawn`は、`alloc`・`spawn`・`panic`と子の効果`E`を、呼び出し側の上限へ要求する。タスク生成時の実行基盤の失敗は`panic`とする。`task::join`はハンドルを消費し、`wait`効果を持つ。

正常にscopeを抜ける前に、すべての子をjoinする。明示的にjoinしなかったハンドルの終了処理と、scope終了の後始末も`wait`を要求する。親からの`return`や`?`でも、この規則を適用する。

未使用のTaskを終了するときは、子の結果も終了するため、`final(Task<s, T, E>) = {wait} ∪ final(T)`とする。明示joinでは結果Tの所有を呼び出し側へ渡し、その後の終了は呼び出し側で追跡する。

切り離したタスク、強制キャンセル、子だけから回復できるpanicは0.1に含めない。子のpanicもプロセス全体を終了する。タスクの使用箇所や効果を、ハンドルを隠して消してはならない。

### 11.3 不変共有

`Share<T>`は、`T: Value + Send + Sync`である内容を深く不変として保持する所有ハンドルである。

- `share::freeze(move value)`で、持ち出せる所有値を消費して作る。`alloc`・`panic`効果を持つ。
- `share::clone(handle)`で明示的にハンドルを複製する。実装上のカウント上限などを考慮し、上限効果は`panic`とする。
- `share::read(handle)`は読み取りviewを作る。変更viewは作れない。
- `Share<T>`は`Value`・`Send`・`Sync`だが`Copy`ではない。

共有ハンドルの複製は、内部の可変状態を共有する手段にはならない。変更したい場合は、読み取った内容を`copy`して、独立した所有値を作る。

### 11.4 通信

標準のチャネルは`T: Send`な所有値を移譲する。送信で値を消費し、受信側だけがその所有を得る。送信に失敗した場合は、値の所有を失敗結果に含めて返す。

0.1は複数送信者・単一受信者のチャネルを持つ。送信者の追加は明示的な標準操作とし、一般の`copy`は使わない。受信者を複製できない。エンドポイントは`Send`だが`Value`・`Copy`・`Sync`ではない。

エンドポイントの終了は、論理的な切断を記録し、待機中の相手を起こす。残ったメッセージを終了する可能性があるため、終了効果に`final(T)`を含める。最後の送信者がなくなりキューが空ならrecvはNoneを返す。受信者がなくなればsendは値を含むErrを返す。

domainとそのキーを別タスクへ渡すこと、任意の共有可変参照、ユーザーが直接操作するatomic型は0.1に含めない。独立した値の移譲、不変共有、チャネルを並行処理の基本とする。

## 12. 標準機能

### 12.1 最小のAPI

以下は、各操作の規範的な型の要約である。型引数・効果の表記を短縮するため、この表はソース文法そのものとはしない。

| 操作 | 引数と結果 | 上限効果 |
| --- | --- | --- |
| `vec::new<T>()` | `Vec<T>`を返す | `{}`。空の格納は割り当てない |
| `vec::from_array<T, N>(take array)` | `[T; N]`を消費し`Vec<T>`を返す | `{alloc, panic}` |
| `vec::len(read xs)` | `Usize` | `{}` |
| `vec::filled<T: Copy>(read value, read count)` | 初期化済みの`Vec<T>` | `{alloc, panic}` |
| `vec::push(inout xs, take item)` | `Unit` | `{alloc, panic}` |
| `vec::pop(inout xs)` | `Option<T>` | `{}` |
| `vec::get_copy(read xs, read i)` | `T: Copy`について`Option<T>` | `{}` |
| `box::new(take value)` | `Box<T>` | `{alloc, panic}` |
| `box::into_value(take box)` | `T`。格納だけを回収し、内容の所有を返す | `{}` |
| `box::read(read box)` | `read T`を投影 | `{}` |
| `box::write(inout box)` | `inout T`を投影 | `{}` |
| `vec::with_split(inout xs, read mid, callback)` | `Result<R, BoundsError>` | コールバックの呼び出し効果と終了効果 |
| `arena::alloc(inout arena, take value)` | `CellRef<d, T>` | `{alloc, panic, final(T)}` |
| `cell::read(read cell, read key)` | `read T`を投影 | `{}` |
| `cell::write(read cell, inout key)` | `inout T`を投影 | `{}` |
| `cell::same(read a, read b)` | 同じdomain内のセルの同一性を`Bool`で返す | `{}` |
| `channel::new<T>()` | `(Sender<T>, Receiver<T>)` | `{alloc, panic}` |
| `channel::clone_sender(read sender)` | `Sender<T>` | `{alloc, panic}` |
| `channel::send(inout sender, take value)` | `Result<Unit, SendError<T>>` | `{alloc, wait, panic}` |
| `channel::recv(inout receiver)` | `Option<T>` | `{wait}` |
| `assert(read condition: Bool)` | 偽ならpanic、真ならUnit | `{panic}` |
| `drop(take value: T)` | 所有する値を終了する | `{final(T)}` |

`with_split`のcallbackは二つの`inout Span<T>`を受け取る一回呼び出しの局所的な関数値である。`mid > len`ならcallbackを呼ばず、`Err`を返す。結果`R`は、二つのSpanへの依存を含んではならない。元のVecはcallbackの終了まで借用される。

呼び出さない場合もcallbackの所有を終了するため、その終了効果を要求する。標準の所有引数の型は、必要な終了効果と局所性の変数を保持して検査する。

### 12.2 配列とSpan

固定長配列、Vec、Spanは、境界検査付きの`[i]`による読み取り・変更・投影を持つ。要素の所有を取り出すには、`Copy`なら複製し、それ以外は`pop`など、全体の初期化状態を保つ所有操作を使う。`move xs[i]`で配列に穴を開けることは禁止する。

Spanは、対象のアドレスと長さを内部に持つ非所有viewであり、0.1では第一級の所有値にならない。反復子が借用を含む場合も、同じ局所性の規則に従う。

### 12.3 文字列

Stringは常に有効なUTF-8を保持する。バイト列からの変換は検査し、失敗を`Result`で返す。整数によるStringの直接索引は禁止し、文字またはバイト列への明示的な操作を使う。書き換えによって不正なUTF-8を生成できるAPIを公開してはならない。

数値の型変換は`num`、ビット演算は`bits`の名前付き標準関数として提供し、任意の型を再解釈するcast演算子は持たない。範囲を狭める変換はResultを返すか、明示的なwrapping操作として区別する。

### 12.4 割り当てと共有の実装

通常の所有格納は、所有の終了に従って回収する。domainの格納は領域単位で回収する。Shareは不変共有の管理を持つ。一般のトレーシングGCを0.1の必須要件にはしない。

処理系は、循環するセルハンドルを追跡GCで解決する代わりに、domainの一括回収を実装できる。チャネルなどの資源の循環で使用されなくなった資源が残る可能性は、メモリ安全性と区別する。

## 13. 外部契約と接続

### 13.1 契約、接続、利用を分ける

`.aya`ソースは外部契約を宣言できるが、任意の外部実装が正しいと宣言する権限は持たない。実物との接続は、別の`.aya-bind`接続設定で行う。

0.1は、まず同期呼び出しの`sync_bytes`プロファイルを定める。保持するポインタ、コールバック、外部からのスタック巻き戻し、非同期のDMA操作はこのプロファイルでは禁止する。

```aya
extern contract Codec @sync_bytes("C") {
    fn decode(read input: Bytes, inout output: Bytes) -> Usize;
}
```

この宣言は、契約を要求するだけであり、相手への信頼を受け入れたことにはならない。宣言から、対応するSessionを受け取る呼び出しAPIを生成する。

### 13.2 sync_bytesの契約

引数型は、整数スカラー、Boolを表すwire用の`U8`、`Bytes`の`read`・`inout`に限定する。戻り値は整数スカラーまたはUnitに限定する。生ポインタ、通常の参照、任意の構造体、Ayaのenumはwire型として直接受け取らない。

wireの整数スカラーはI8〜I64、U8〜U64、Usizeとする。BoolやCharをwireへ直接写像せず、必要なら受信後に有効性を検査して変換する。

Bytesは、C ABIでは、readなら`const uint8_t*`と`size_t`、inoutなら`uint8_t*`と`size_t`の二引数へ、元の引数順に展開する。Usizeはsize_t、固定幅整数は対応する固定幅のC整数とする。inoutは、長さと格納先を変更できない初期化済みの固定範囲として渡す。

接続が受け入れる条件の識別子は、次の固定集合とする。

| ID | 外部に要求する条件 |
| --- | --- |
| `ABI` | エントリー、引数、戻り値、制御の復帰が宣言したABIに従う |
| `FRAME` | ホスト側の領域へは、渡した範囲・読み書き権限とABIが許す範囲だけでアクセスする |
| `RETAIN` | 呼び出し終了後に、渡した領域へのアクセス能力を残さない |
| `CONTROL` | コールバック、外部からの巻き戻し、未宣言のホスト制御移動を行わない |

内部のアダプターは、バッファの生存、渡す範囲、ピン留め、Aya側の競合防止、wire値の変換を保証しなければならない。相手が無期限に戻らないことは、メモリ安全性だけでは禁止しない。

生成APIの効果上限は`{external(Codec), io, wait}`とする。`io`は外部の作用の保守的な上限であり、実際に入出力するとは限らない。Sessionの取得時の失敗などは別のAPIで扱う。

### 13.3 未検証の信頼を受け入れる設定

次は`.aya-bind`のソース例である。`aya-binding`は説明用のコードフェンス名とし、処理系の実装を意味しない。

```aya-binding
unsafe binding decoder: image::Codec {
    target = native("vendor/libcodec", prefix = "codec_");
    artifact = "deployment-pinned-artifact";
    accept = [ABI, FRAME, RETAIN, CONTROL];
}
```

`unsafe`は、0.1ではこの`unsafe binding`にだけ現れる。通常の`.aya`のブロックや関数へ付けることは禁止する。接続ファイルは、リンクするプログラム構成の一部であり、通常のimportから追加してはならない。

`accept`は、当該プロファイルが要求する未検証の条件を漏れなく列挙する。未知の条件や、関係のない内部命題は記述できない。列挙は条件の成立を証明するものではない。

targetとartifactは、配備時に特定の成果物と設定へ解決しなければならない。識別子、ハッシュ、署名だけで契約の正しさが証明されたと扱ってはならない。

native対象のロード時初期化も接続の信頼範囲に含める。コンパイラは、通常の型検査や名前解決のために外部のnativeコードを実行してはならない。

### 13.4 接続の権限

`Session<C>`は外部接続の権限であり、`Value`・`Copy`・`Send`・`Sync`ではない。通常のコードは構築できず、起動時に渡される`Root`の許可された接続から取得する。

```aya
fn decode_count(inout session: Session<Codec>, read input: Bytes)
    -> Usize !{alloc, panic, external(Codec), io, wait} {
    var out = vec::filled(0u8, 4096usize);
    let count = Codec::decode(&session, input, &out);
    assert(count <= vec::len(out));
    return count;
}
```

生成された`Codec::decode`は、先頭に`inout Session<Codec>`を要求する。Sessionを排他的に借用して、一つのSessionに対する重なる呼び出しを拒否する。ただし、外部の非再入なグローバル状態を守る必要があるなら、接続設定がSessionを一つだけ発行するなど、その契約も維持しなければならない。

この例は、戻り値の範囲を確認するが、外部が呼び出し中に領域外を書いた場合の破壊を取り消せない。未検証のnative接続を使う構成の安全性は、受け入れた契約が成立することを前提とする。

### 13.5 保護された接続

隔離された実行先と、境界の検査を実装するプロバイダーは、native接続の代わりに同じAya側のAPIを提供できる。ただし、APIが同じだけでは、同じ保証を主張できない。

保護されたプロバイダーを認めるには、どの条件を境界機構が強制し、どの実行基盤を前提とするかを、処理系のプロバイダー定義に含める必要がある。0.1は、任意のユーザーが文字列で`verified`と記述して未検証条件を消す機能を持たない。

効果`external(C)`は、接続先を変更しても残る。未検証の信頼への依存は、リンク時の構成報告として、関数の効果とは別に記録する。

### 13.6 非同期の外部操作

DMA、非同期コールバック、外部が保持するバッファの一般的なプロファイルは0.1に含めない。追加時は、所有する転送中の資源、停止・完了の契約、失敗時の保留・隔離を仕様化しなければならない。

単に`sync_bytes`の`RETAIN`条件を外す変更は禁止する。タイムアウトや失敗の結果だけで、外部が使う資源をAyaの通常の所有へ戻してはならない。

## 14. モジュールとエントリーポイント

### 14.1 モジュール

一つのソースファイルは、先頭の`module name;`でモジュールを宣言する。`use std::vec;`のように名前を導入する。公開する項目に`pub`を付け、それ以外はそのモジュール内に限定する。

組み込み型、Option/Resultのvariant、`assert`・`copy`・`drop`は標準preludeから導入する。本文の断片では`use std::vec;`などの標準モジュールの導入を省略する。タプルは`.0`・`.1`でフィールドを選べ、`let (a, b) = e;`のように所有を分解できる。

定数は、実行時効果のない閉じた式で初期化する。可変のグローバル値や、モジュール初期化での任意の外部I/Oは認めない。

### 14.2 抽象型

実装を隠す公開型は、そのモジュールが提供する`Value`・`Copy`・`Send`・`Sync`の特性と、ブランド・効果の依存を公開インターフェースに記録する。

実装を隠したことを理由に、制約を消してはならない。公開した特性が内部表現から成立しない場合は、そのモジュールのコンパイルを拒否する。

### 14.3 起動

実行プログラムは、`pub fn main(take root: Root) -> I32 !E`を一つ持つ。Rootは起動時にランタイムだけが作り、`Value`・`Copy`・`Send`・`Sync`ではない。

Rootから得られる外部接続や標準I/Oの権限は、プログラムの接続設定によって制限する。通常の関数は、Rootや他の権限を引数・捕捉で受け取らない限り取得できない。

`root::session<C>(&root, name)`は、対応するSessionが未取得であれば移譲する。存在しない、型が違う、取得済みなどの場合は`Result::Err`とする。0.1では同じ接続についてSessionを一つだけ発行する。

Sessionはロード済み接続への権限であり、外部の処理中バッファなどを所有しない。SessionとRoot自体の終了効果は空とする。接続のロード・終了はプログラム構成の初期化・終了として報告する。外部のFileなどの所有資源を追加するプロファイルでは、別途その終了契約と効果を定める。

## 15. 実行とエラー

### 15.1 実行のモデル

所有する格納、領域、借用、タスク、外部接続を区別する。内部のポインタ表現やアドレス幅は処理系の実装事項だが、ソースの許される操作と観察できる結果を変えてはならない。

未定義動作を、受理した通常の内部ソースの意味として導入してはならない。検査に失敗する操作は、仕様に従ってエラーまたはpanicになる。

### 15.2 異常終了

panicはスタックを巻き戻さず、全タスクを含めプログラムを終了する。終了処理の実行に依存して、他の実行中タスクから参照される格納を早期回収してはならない。

ホストOS・ランタイム・装置を含む実行環境には、プログラム終了時に外部アクセスを止めるか、その資源を安全に保留する責任がある。Ayaの型検査だけで、任意の装置の暴走や、契約を破るnativeコードへ耐える保証を主張しない。

### 15.3 診断

拒否時には、少なくとも次を区別し、原因の箇所と競合する使用を示す。

- 移譲済み・未初期化の格納先の使用。
- 重なるreadとinout、または複数のinout。
- 局所格納・投影・ブランドの持ち出し。
- キーのブランドの不一致、キーの借用競合。
- 不足する効果、Send条件、呼び出しモード。
- 外部契約・接続・必要な権限の欠落。

## 16. 構文の骨格

以下は主要構文のEBNFである。リテラル、演算子、型の意味は前節の規則で補う。静的な型検査とモード検査を、構文だけで表しているわけではない。

```text
module        = "module" path ";" { use | item } ;
use           = "use" path ";" ;
item          = ["pub"] (function | view | structure | enumeration | trait | impl | contract | constant) ;
structure     = ["resource"] "struct" name [generics] "{" { field } "}" ;
enumeration   = "enum" name [generics] "{" { variant } "}" ;
field         = ["pub"] name ":" type "," ;
function      = "fn" name [generics] "(" [parameters] ")" ["->" type] [effects] block ;
view          = "view" name [generics] "(" [parameters] ")" "->" ("read" | "inout") type effects block ;
parameter     = ["read" | "inout" | "take" | "init"] name ":" type ["@local"] ["@final" effect_set] ;
parameters    = parameter {"," parameter} [","] ;
generics      = "<" generic {"," generic} ">" ;
generic       = name [":" bounds] | "brand" name | "effect" name ;
bounds        = path {"+" path} ;
type          = path ["<" type_argument {"," type_argument} ">"]
              | "(" [type {"," type}] ")" | "[" type ";" integer "]"
              | "fn" ("many" | "mut" | "once") "(" [function_slots] ")" "->" type effects ;
type_argument = type | name ;
function_slot = ["read" | "inout" | "take" | "init"] type ["@local"] ["@final" effect_set] ;
function_slots = function_slot {"," function_slot} ;
effects       = "!" (name | "{" [effect {"," effect}] ["|" name] "}") ;
effect        = name | "external" "(" path ")" | "final" "(" type ")" ;
effect_set    = "{" [effect {"," effect}] ["|" name] "}" ;
block         = "{" { statement } "}" ;
statement     = ["local"] ("let" | "var") pattern [":" type] ["=" expression] ";"
              | ("read" | "edit") name "=" expression ";"
              | place assign_op expression ";"
              | "return" [expression] ";"
              | "yield" ["&"] place ";"
              | "domain" name "as" "(" name "," name ")" block
              | "scope" name block
              | if | while | match | block
              | "break" ";" | "continue" ";" | expression ";" ;
expression    = literal | place | call | constructor | closure | if | match
              | "move" place | "copy" "(" expression ")"
              | expression "?" | unary_op expression | expression binary_op expression ;
closure       = "fn" "[" [captures] "]" "(" [parameters] ")" ["->" type] [effects] block ;
capture       = ("read" | "inout" | "take") name ;
captures      = capture {"," capture} ;
place         = path | place "." (name | integer) | place "[" expression "]" ;
call          = expression "(" [argument {"," argument}] ")"
              | path "<" type_argument {"," type_argument} ">" "(" [argument {"," argument}] ")" ;
argument      = ["&"] expression ;
constructor   = path ["<" type_argument {"," type_argument} ">"]
                ("{" [name ":" expression {"," name ":" expression} [","]] "}"
                | "(" [expression {"," expression}] ")")
              | "[" [expression {"," expression}] "]" ;
pattern       = name | "_" | "(" pattern {"," pattern} ")"
              | path "(" pattern {"," pattern} ")"
              | path "{" [name [":" pattern] {"," name [":" pattern]}] "}" ;
if            = "if" expression block ["else" (block | if)] ;
while         = "while" expression block ;
match         = "match" expression "{" {pattern "=>" (expression | block) ","} "}" ;
trait         = "trait" name "{" {"fn" name "(" [parameters] ")" "->" type effects ";"} "}" ;
impl          = "impl" path "for" type "{" {function} "}" ;
constant      = "const" name ":" type "=" expression ";" ;
contract      = "extern" "contract" name "@sync_bytes" "(" string ")"
                "{" { "fn" name "(" [parameters] ")" "->" type ";" } "}" ;
path          = name {"::" name} ;
```

`let`には初期化式を必須とし、`read`・`edit`の式は投影可能でなければならない。`&`は、引数のinout/init、inoutのyield、mutクロージャの呼び出しに限る。任意の整数へ変換できるアドレス取得演算子ではない。

優先順位は、強い順に、フィールド・索引・呼び出し・`?`、単項演算、乗除・剰余、加減、大小比較、等値比較、`&&`、`||`とする。同じ比較の連鎖は禁止し、算術は左結合とする。代入は文であり値を返さない。

traitは関数シグネチャの集合、implは対応する本体の集合とする。ユーザー定義の演算子やマクロは0.1に含めない。配列長の`N`は、組み込み配列操作の長さパラメータであり、一般のユーザー定義const genericsは後続版とする。

単項演算は`!`と`-`、二項演算は`+ - * / % < <= > >= == != && ||`、代入は`= += -= *= /= %=`を持つ。条件はBoolを要求する。Variantのフィールド、構築、パターンは3節に従う。関数を呼び出す式に加え、`(&f)`と`(move f)`を関数値の呼び出し位置で認める。

`.aya-bind`の初期構文は、次に限定する。

```text
bindings = { "unsafe" "binding" name ":" path "{"
               "target" "=" "native" "(" string "," "prefix" "=" string ")" ";"
               "artifact" "=" string ";"
               "accept" "=" "[" name {"," name} "]" ";"
             "}" } ;
```

## 17. 適合性の例

次は、一つのモジュールとして書いた所有値の例である。

```aya
module ownership_example;
use std::vec;

pub fn main(take root: Root) -> I32 !{alloc, panic} {
    let original = vec::from_array([1i64, 2i64, 3i64]);
    var independent = copy(original);
    independent[0] = 9;
    assert(original[0] == 1);
    assert(independent[0] == 9);
    return 0;
}
```

Rootは使用しなくても終了できる。外部への権限は、この例では取得しない。

この表の「受理」「拒否」は、今後の処理系が満たすべき判定であり、実装で確認済みという意味ではない。周辺の型・効果が適切に宣言されていることを前提とする。

| ID | プログラムの条件 | 判定・結果 |
| --- | --- | --- |
| V01 | ValueなVecをcopyし、片方の要素を変更する | 受理。他方の内容は変化しない |
| V02 | Vecをmoveした後、元の束縛を読む | 拒否 |
| V03 | キーやSessionをcopyする | 拒否。Valueではない |
| B01 | 同じ値を同時にreadとinoutへ渡す | 拒否 |
| B02 | 同じ構造体の異なるフィールドをeditする | 受理 |
| B03 | view内の局所変数をyieldする | 拒否 |
| B04 | with_splitで得た二領域を、callback内で変更する | 受理。境界不正時はcallbackを呼ばない |
| I01 | init関数が一部の正常経路で出力を書かずに戻る | 拒否 |
| I02 | inoutをmoveし、再初期化せずErrを返す | 拒否 |
| L01 | localなVecを所有のまま返す | 拒否 |
| L02 | localなVecの整数要素を返す | 受理。整数の独立した複製 |
| L03 | localなValueをcopyして返す | 受理。通常の所有格納へ複製する |
| D01 | 一つのキーをreadして、複数セルを読む | 受理 |
| D02 | 読み取り投影を後で使うのに、同じキーをinoutで借りる | 拒否。対象セルが異なっても不可 |
| D03 | 別domainのキーでセルを読む | 拒否 |
| D04 | domainのセルハンドルを外へ返す | 拒否 |
| D05 | Nodeのnextを相互に設定して循環を作る | 受理。domain終了で一括回収 |
| C01 | manyなクロージャをonceスロットへ渡す | 受理 |
| C02 | 所有捕捉を返して消費するクロージャをmanyとして使う | 拒否 |
| T01 | Vecを所有捕捉して子タスクへ渡す | Sendなどを満たせば受理 |
| T02 | キー、セルハンドル、親のread捕捉を子へ渡す | 拒否 |
| T03 | scopeの外へTaskを返す | 拒否 |

| E02 | !{}の関数で、局所的なinout引数だけを変更する | 他の失敗・効果がなければ受理 |

## 18. 保証と未確立の点

### 18.1 内部の検証義務

処理系は、所有の一意な終了、借用の競合防止、局所性の保持、ブランドの生成・不変性、構造的なSend/Sync、効果の包含、外部境界での表現変換を検査しなければならない。

標準基本操作は、通常のソースにない低水準表現を内部で使っても、公開する型と規則の安全性を保たなければならない。組み込みへ移したことだけを、証明として扱ってはならない。

### 18.2 外部に対する主張

未検証の接続の契約が成立し、実行基盤が仕様に従い、内部の処理系・基本操作が本仕様を正しく実装する場合に、内部のメモリ安全性と競合防止を主張する。

契約を破る外部コードからも内部を守る主張は、接続プロバイダーが強制する境界と、その検証対象の範囲に限定する。

### 18.3 次の検証

0.1の型体系や進行・保存の証明、処理系、ABIの実装は存在しない。本書の規則と例を、[設計判断と検証計画](design.md)の順序で具体化する。全機能を統合した安全性がすでに確立したとは主張しない。
