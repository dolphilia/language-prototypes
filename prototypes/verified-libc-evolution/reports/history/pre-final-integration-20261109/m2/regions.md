## 台帳と権限

一つの所有領域に対応する台帳に、所有者、世代、次の借用識別子、容量、生存状態、現在の借用を持たせる。各借用には識別子・所有者・世代・開始位置・長さ・書き込み可否がある。

これらの値を書き込むだけでは、操作を許可しない。有効な台帳と許可された遷移を条件とする。

| 操作・性質 | 検査した内容 |
| --- | --- |
| 初期台帳 | 借用なしの台帳が整合し、所有者が使用できる。RAMの存在・所有は別の外部契約 |
| 借用の追加 | 容量内、現在の所有者・世代、新しい識別子、既存の借用との両立を満たす。追加後も台帳が整合する |
| 読み取りの共有 | 読み取り同士は重複できる |
| 排他的な書き込み | 別の有効な借用と同時に許可される場合、その領域は分離している。重複した書き込み借用は拒否する |
| 所有者の使用 | 借用が存在する間、領域全体の所有者による使用は停止する。最後の借用を返すと使用できる |
| 返却 | 対象の識別子を台帳から除き、その借用を使用できなくする。台帳の整合性を保つ |
| 失効 | 借用がないときだけ失効できる。生存を解除して世代を進める。古い世代の借用を次の世代で再使用できない |
| 遷移列 | 整合した台帳から許可された操作を順に実行すれば、任意の有限長の列の後も整合する |

これは**一つの現行台帳を受け渡す逐次的なモデル**である。HOLの命題自体を線形資源に変えたものではない。過去の台帳を複製して独立した実行へ渡すことや、並行する実行の権限の併合を許可する仕組みは作っていない。外部の利用者が一つの所有の根と現行台帳に従うこと、所有者の識別子が実際の領域に対応することは契約に残る。一般の借用検査器や並行メモリの検証を達成したとは扱わない。

現行台帳の受け渡しは、将来の型検査器や限定した構築APIで強制できるソフトウェア上の制約である。このプロトタイプに検査器がないことと、原理的にソフトウェアで扱えない限界とは区別する。RAMの物理的な有効性と同じ意味で不可避の信頼と呼ばない。

## 分割と、ライブラリへの接続

成功条件を`0 < split < L`、`n <= split`、`n <= L-split`とした。根となる領域には非NULL・非折り返し・コードとの非重複という幾何学上の条件を与える。

ここから、次をHOLで導いた。

1. `src=arena`と`dst=arena+split`が非NULLであり、長さとアドレスが折り返さない。
2. 両方の範囲が元の容量内にあり、コピー元とコピー先が重複しない。
3. コピー先とコードが重複しない。
4. 元の部分から読み取り借用、後ろの部分から書き込み借用を作れ、領域全体の所有者の使用は停止する。
5. それと同じ`L`・`split`・`n`に対して、M1の機械語の機能・有限復帰・保存・途中のアクセスの契約を利用できる。
6. 両方の借用を返して、所有者の使用を再開できる。

`regions:abstract-protocol`は、借用の生成・使用権限・返却とコピーの機械語契約を、一つの閉じた命題へ接続している。成功時の抽象操作は開始時の入力をコピーし、出力範囲の外と元の読み取り部分を保存する。失敗時は1を返し、領域内を変更しない。

**ここでの機械語契約は、検査済みの引数がコピー関数の入口レジスタへ入った時点から始まる。** 検査の分岐、引数を作る命令、`BL`、スタック、リンク後の呼び出し元は、E5・E3bで接続する。失敗時の性質も、現時点では抽象操作の定理である。

## 拒否例と、減算の扱い

重複した排他的借用、容量を越える借用・分割、不正な分割位置、借用中の失効、返却後・失効後の使用を、実機の不正ポインタの試験ではなくモデル内の定理で拒否した。対照として、重複する読み取り借用は構成できることも確認した。

自然数の`16-17`は0であり、`n <= L-split`だけでは`split < L`を導けない。アドレス計算も、範囲の前提を欠けば折り返す例がある。したがって、減算を容量として解釈したり、部分領域のアドレスを正当化したりする前に、必要な条件を導く。

これとは別に、機械語の符号なし減算を先に実行しても、その結果を検査前に使わなければ必ず不正になるわけではない。命令の順序だけを反例とはせず、失われた条件と実際の使用箇所を調べる。E3bの最初の実装では、計画どおり範囲検査の後に減算・アドレス計算を置く。

## 残る外部への信頼と費用

根となる通常RAMの存在、有効性と寿命、排他的な所有、OSによる維持、所有台帳と実際のメモリの対応は外部契約である。初期台帳の整合性を証明しても、OSからRAMを確保したことにはならない。ISAモデル・論理カーネル・実行環境・抽出器の信頼もM1から残る。

識別子・世代・台帳は証明用であり、この段階で新しい実行コードやデータは生成しない。実行時に権限検査用の容量や時間を追加した結果ではない。実際の長さ検査・呼び出し・スタックの費用はE3b・E5で測る。

```sh
# M1の完了監査と同じ入力・成果物がそろった環境で実行する。
python3 prototypes/verified-libc-evolution/tools/verify_regions.py
```

入力が検査中に変わった場合、M1が未完了の場合、古い結果・例外・不足した定理・追加公理がある場合は失敗する。
