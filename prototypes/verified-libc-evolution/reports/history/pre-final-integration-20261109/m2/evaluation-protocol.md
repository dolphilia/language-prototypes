# M2の評価方法

E4の性能測定前に固定する。M1の測定・方法は変更しない。E5・E3bの呼び出し元の測定方法は、実物の接続がそろった後、その測定を始める前に別節へ固定する。

## E4: 重複コピー

- 同じ新しいCハーネスで`vp2_memmove`とシステムの`memmove`を比較する。両方をvolatileな関数ポインタから呼び、組み込み関数への置換とLTOを無効にする。
- 長さはM1の21種類（0・1・2・4・7・8・9・15・16・17・31・32・33・63・64・255・256・1024・4096・32768・1MiB）。元の位置のずれは0・1・7。コピー先との差は0・±1・±n。同一ケースに重なる差は除く。
- 各ケースの`vp2_memmove`を8ms以上になるまで較正する。長さ4096以上は反復1から、それより小さければ1024から始める。両実装を同じ反復数で測る。
- 各実装を7個の別プロセスで測る。seed `0x19273645`で各試行内の実装順を並べ替え、PID・較正・順序・生データを保存する。
- M1と同じ中央値・四分位と5%の判定規則を使う。逆方向、同一アドレス、短い長さ、整列のずれも結果へ残す。最速性や秒数の上限を主張しない。
- ウォームアップは4096呼び出し、かつ4MiB以下。長さ32768未満は一つの領域、それ以上は合計128MiB以下の作業領域を回して使う。初期化とチェックサムの計算は測定区間の外へ置く。
- 作業領域の大きさはキャッシュの追い出しやコールド状態を保証しない。OSの割り込み・他の処理・熱の影響は残る。CPU名の取得が拒否された場合は、アーキテクチャと診断を保存し、CPU名は推定しない。
- 測定値には関数ポインタによる呼び出しとループの費用も含む。小さい領域では同じポインタを再利用し、大きい領域では領域を回す添字計算も含む。関数内部だけの命令時間と混同しない。
- 形式検査と同じオブジェクト・リンク後の関数を測る。測定前後の入力、証明、実物の対応を照合する。証明中のプロセスと測定を同時に走らせない。
- 本体68バイト、オブジェクト、配置余白、同じbasenameを持つ容量用実行ファイル、M1の2関数を含む配布用の本体合計を別々に記録する。システムlibcの共有コードを実行ファイルの容量から無視したまま、静的な本体と大小比較しない。

速度改善の有無と、E4の実装・証明・評価の完成を分けて判定する。
