# M1で使用する命令の差分検査

状態: **完了**。新規HOLプロセスで46,080件の閉じた検査を2286.7秒で受理し、追加公理なしを確認した。[入力・対象・結果](verification.json)と、圧縮した[QEMUの観測](qemu-cases.jsonl.gz)・[実機の観測](native-cases.jsonl.gz)を保存している。未解決の不一致は0件である。

対象はM1の13個の正常生成物に現れる20形式・33エンコーディング。各形式に32境界例と固定シードの256例を用意し、QEMUと実機で各5,760例を観測する。

QEMUの[公式GDB仕様](https://www.qemu.org/docs/master/system/gdb.html)を用い、OSなしの`virt / cortex-a72 / TCG`で一命令ずつ実行する。[10.1.0の版](https://github.com/qemu/qemu/releases/tag/v10.1.0)と実行バイナリのSHA-256を[専用の固定情報](../../../isa-backend.lock.json)に保存した。配布済みのHomebrewバイナリを利用しており、この実験でソースから再ビルドしたとは扱わない。上流タグと配布バイナリのソース対応を証明したものでもない。通常の検査はネットワークを使わない。

## 比較の意味

観測した入力オペランドから観測した出力が得られる一ステップの`ensures_n`を、HOLのARM意味論で証明する。同じ命令の他のレジスタ、フラグ、メモリの保存は変更範囲で確認し、観測した32レジスタ・NZCV・512バイトの保存も検査する。ロード値またはストア先の値はその幅で比較する。初期状態が存在し、数値条件を満たし、一ステップの有限実行へ接続することも確認する。

具体例の初期状態は必要な入力オペランドとロード範囲を構成する小さな証人である。観測した512バイトすべてをその証人に列挙してはいない。一方、一ステップの定理は指定したロード値以外のメモリを任意とし、正確な変更範囲を保証する。観測した残りのメモリが保存されたことは別に照合する。

実機では、データ領域、SP、Darwinが予約するX18、PC/LRを安全な値に置き換える。実機の実際の入力と出力を別々にHOLで検査し、バックエンド間は置き換えた値を除くレジスタ、相対分岐先、フラグ、データを比較する。異なるアドレスの全状態が文字通り同一だとは主張しない。命令片は静的に組み立て、分岐先を専用の着地点に限定し、JITや任意ポインタの実行を使わない。

バイトアクセスは未整列と領域の最後の1バイトを含み、64ビットアクセスは8バイト整列した通常RAMの最終8バイトまでを扱う。これにより64ビット未整列アクセス、例外、MMIO、並行性、特権状態全体を検査したことにはしない。実機の全アクセスイベント、キャッシュ、投機、電力は観測していない。

一致は有限の試験に対する根拠であり、QEMU・HOL・全CPUの意味論の同値定理ではない。命令一覧、試験生成器、GDB通信、実機の捕捉コード、Mach-O抽出器、OS・CPUは残る信頼の境界である。

```sh
python3 prototypes/verified-libc-evolution/tools/verify_isa.py
```

前提はM1の完了と、固定したQEMU実行ファイルの導入である。SHA-256が異なる環境を暗黙に受け入れず、固定情報の更新と再検査を別の変更として扱う。
