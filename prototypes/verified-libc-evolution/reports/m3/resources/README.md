# 命令ステップ数とデータアクセス量

状態: **完了**。新規HOLプロセスで20件の閉じた定理を219.6秒で検査し、追加公理なしを確認した。[証明の入力と結果](verification.json)を保存している。

対象は、保存した基本コピー、埋め込み、長さ8専用版と、M1の任意長コピーである。関数の入口から復帰命令までのARM関係のステップ数を`ensures_n`で扱う。単なるソースの数え上げではなく、実際のMach-Oオブジェクトの命令から、任意の有効な長さについて証明する。

| 実装・経路 | モデル上のステップ数 |
| --- | --- |
| 基本コピー | `5n+3` |
| 埋め込み | `4n+3` |
| 長さ8専用版・nが8以外 | `5n+5` |
| 長さ8専用版・整列済みの8バイト | `8` |
| 長さ8専用版・未整列の8バイト | `48` |
| M1・整列済み | `7(n DIV 8)+5(n MOD 8)+10` |
| M1・未整列 | `5n+7` |

整列済みは入力と出力がともに8バイト整列している経路である。公開契約へ追加の整列・余分な容量・サイズ上限を導入しない。ゼロ長と端数も式に含む。

## データ量と復帰の意味

コピーはnバイトを読みnバイトを書き、埋め込みは読み0・書きnとなる。イベントのバイト幅を加算する二つの再帰関数を定義し、イベント列のAPPENDに対する加法性を証明した。逆順のイベント蓄積でも加算量は変わらない。開始前の任意のイベント列の量と、今回増えた量を分ける。命令の取得はデータアクセス量に含まない。

ステップ付きの合成則をHOL内で証明し、ワード反復と端数処理を関数全体へつなぐ。基盤の通常のbig-step補助はステップ数を扱わないため、同じ状態更新の処理を使う数付きの補助を用意した。補助自身を公理にはしていない。

この定理は、指定した回数のモデル実行の終点を保証する。呼び出し先の返却先が自身の入口等と一致する場合も、入口条件に新しい禁止事項を足さない。「PCが返却先の値になった最初の時刻」を最小化する定理ではない。

本体は葉関数でSPを変更せず、SPを基点とするロード・ストアを持たない。フレームにもSPを含めない。専用スタック、ヒープ、証明のための実行処理はいずれも0である。利用者が渡す入力・出力領域はこの0に含めていない。

## 古い式を拒否する具体例

基本ループの復帰前へNOPを追加すると、n=0の実際の復帰は4ステップになる。古い式の3ステップの終点は返却先ではない。CBZを削除した版では、n=1の復帰は7ステップになる。返却先をコードの入口にした有効な初期状態では、古い8ステップの終点が返却先から進んでいる。

どちらも有効な公開事前条件を満たす初期状態・数値条件・有限実行を証明する。証明戦術の失敗を反例と呼ばず、時間計測から命令数を推定しない。返却先が自身のコード内であることは元の契約で禁止されていない。

## 残る前提

これはモデル上の命令数と通常RAMのデータ量である。パイプライン、キャッシュ、投機、競合、OSスケジューラ、ページフォルト、CPU周波数等を含む秒数の上限ではない。RAMの実在・寿命・有効性、ISAモデルとCPU、論理カーネル・実行環境への信頼は残る。
