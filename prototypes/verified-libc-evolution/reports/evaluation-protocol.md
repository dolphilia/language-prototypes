# 評価方法の固定

2026-11-08。性能の測定前に固定する。詳細な必須条件は[M1](../../../docs/plans/verified-libc-evolution/phase-1-composition.md)と[後続段階](../../../docs/plans/verified-libc-evolution/later-stages.md)を維持する。

- 同じ新しいCハーネスで既存の基本版・長さ8版・新しい任意長版・libcを測る。過去のns値を混ぜない。
- 長さ0・1・4・7・8・9・15・16・17・31・32・33・64・256・4096・32768・1MiB、整列の組(0,0)・(1,0)・(0,1)・(1,1)・(7,7)を含める。
- 基本版の各ケースが8ms以上になるよう反復を調整する。大きな長さの反復は1から始め、ウォームアップもバイト数で制限する。バッファの既定合計上限は128MiB。
- 少なくとも7個の別プロセスの試行を保存する。中央値が比較対象の0.95倍未満で、上位四分位が比較対象の下位四分位より小さいとき改善、逆向きなら退行、それ以外は不明とする。
- 整列済み64・256・4096の改善仮説と、短い長さ・未整列の結果を分ける。関数本体、配置余白、オブジェクト、実行ファイルを分ける。容量用ハーネスは同じbasenameを別ディレクトリでリンクする。
- 証明費用は3個の新しいプロセスで、基盤ロード・子の証明・親の証明を分ける。直接版と合成版のオフセット・一時レジスタ・保存範囲の同じ変更について、変更ファイル・補助命題・再検査範囲・時間を記録する。
- 探索は固定した4〜8候補に限り、全契約と資源条件を通ったものだけ測る。整列済み64・256・4096の基本版に対する中央値比の平均で評価し、最良から5%以内なら小さい本体を優先する。
- 選択後は候補を固定して新規検査と7プロセス以上の確認用測定を行う。確認結果を見て選び直したものを独立した確認とは呼ばない。

命令ステップ数と秒単位の性能、証明の完了と性能仮説の支持、観測した修正費用と一般的な開発負担の主張を区別する。
